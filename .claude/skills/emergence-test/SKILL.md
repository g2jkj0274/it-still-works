# 창발 테스트

목적: "부품은 있는데 기계가 안 나오는" 상태를 잡는다. 통과 못 하면 원인은 부품이 아니라 세계 규칙이다.

## 절차
1. `docs/PRIMITIVES.md`에서 현재 마일스톤까지 해금된 부품 목록과 속성만 읽는다. "의도된 쓰임" 열은 가린다.
2. 해금된 세계 규칙 목록(`docs/SIM_ORDER.md`)을 읽는다.
3. 30분(벽시계) 동안 자유 조합. 목표 없이 "이걸 이렇게 놓으면 뭐가 되지"만 반복한다.
4. 작동하는 조합 중 `PRIMITIVES.md`의 "의도된 쓰임"에 없는 것을 고른다. 이제 그 열을 열어 대조한다.
5. 고른 기계 각각을 `test/emergence/<milestone>_<name>.gd` 테스트로 고정한다:
   - 블록 배치 시퀀스 → N틱 진행 → 기대 결과 단언.
   - 실제 게임 액션 API만 사용 (`world.place`, `world.tick`, `player.interact`). 내부 상태 직접 조작 금지.
6. `docs/EMERGENCE_LOG.md`에 기록:
   ```
   ## M? — YYYY-MM-DD
   - [이름] 부품: [...] / 하는 일: [...] / 설계 문서에 있었나: 아니오 / 테스트: test/emergence/...
   ```

## 통과 기준
- 비의도 기계 3개 이상, 각각 테스트로 고정됨.
- 3개 중 최소 1개는 밤 몹 규칙(소리 반응 또는 블록 파괴)을 이용한 것.
- 3개 중 최소 1개는 두 개 이상의 세계 규칙이 결합된 것 (예: 중력 + 신호, 아이템 엔티티 + 몹).

## 실패 시
- 부품을 추가하지 않는다.
- 어떤 세계 규칙이 있었으면 조합이 늘었을지 가설 1개를 적어 보고한다. 예: "떨어진 아이템이 압력판을 누르면 수거·감지 기계가 나온다".
- 그 규칙은 architect 검토 후 태스크가 된다.

## 오용 테스트 (새 부품 추가 시 항상)
- 새 부품마다 의도 외 쓰임 3개를 실제로 배치해 작동시킨다. 3개가 안 되면 부품 설계를 되돌린다.
