# 회로 생존 샌드박스 — 프로토타입 스펙 v0.1

> 상시 적용 규칙은 루트의 `CLAUDE.md`에 있다. 이 문서는 부품 명세와 범위를 정의한다.

> 이 문서는 프로토타입 범위만 정의한다. 여기 없는 것은 만들지 않는다.

---

## 1. 개요

아이소메트릭 복셀 섬에서 살아남는 생존 샌드박스. 낮에는 자원을 모으고 회로 장치를 만들고, 밤에는 그 장치가 시험받는다.

**생존이 목적이고 회로는 수단이다.** 회로 없이도 손으로 살아남을 수 있지만, 반복 노동이 쌓여 점점 힘들어진다. 회로는 강제가 아니라 유혹이다.

### 설계 원칙

| 원칙 | 내용 |
|---|---|
| 회로가 코어 | 개발 시간의 대부분을 회로 시스템에 쓴다. 나머지는 최소한만 |
| 원인을 알려주지 않음 | 에러 메시지 없음. 장치의 동작만 보이고 원인은 플레이어가 추론 |
| 실패는 가벼움 | 죽으면 리스폰. 만든 것은 남음 |
| 목표를 강제하지 않음 | 게이팅 없음. 부품은 처음부터 다 열려 있음 |
| 손으로도 되지만 힘듦 | 불가능이 아니라 반복. 첫 번째는 재밌고 열 번째는 지겹게 |

### 아트 방향

메이플스토리2 톤. 아이소메트릭 고정 시점, 파스텔, 복셀. 밝고 경쾌함. 무겁거나 무서운 연출 없음. 프로토타입 단계에서는 CC0 에셋 또는 단색 프리미티브로 대체.

- 색은 `view/palette.gd` 한 곳에 모은다. 새 블록을 넣을 때도 여기만 고친다
- **명도 0.60 이상, 채도 0.45 이하.** 파스텔의 경계이며 테스트가 지킨다
- 파스텔은 쓸 수 있는 폭이 좁다. 색상환에 고르게 펴야 종류가 구별된다
- 같은 종류라도 칸마다 명도를 아주 조금 달리해 넓은 면이 한 덩어리로 보이지 않게 한다. 자리에서 값을 뽑으므로 무늬는 실행마다 같다
- 캐릭터는 치비 비율. 머리가 크고 몸이 작다
- 그림자는 부드럽게. 또렷한 그림자는 톤을 무겁게 만든다

## 2. 기술 스택

- **엔진**: Godot 4.x
- **언어**: GDScript (성능 병목 발생 시 해당 부분만 C#)
- **테스트**: GdUnit4 (유닛), PlayGodot (E2E)
- **버전관리**: Git, 기능당 브랜치

### 아키텍처 규칙 — 필수

**1. 결정론적 시뮬레이션**

같은 초기 상태 + 같은 명령 시퀀스 → 항상 같은 결과.

- 위치·수량은 정수 격자만 사용. 시뮬레이션 로직에 부동소수점 금지
- 난수는 시드 고정된 단일 RNG 인스턴스 경유. `randi()` 전역 호출 금지
- 딕셔너리 순회 등 순서 비보장 자료구조를 시뮬레이션 판단에 사용 금지
- `StringName` 끼리의 비교는 사전순이 아니라 내부 포인터 순이다. `Array[StringName].sort()` 는 실행마다 순서가 달라진다. 정렬이 필요하면 `String` 으로 바꾼 뒤 정렬

**2. 틱 기반 고정 시간**

- 시뮬레이션은 고정 20 tick/s 로 진행. 렌더 프레임과 분리
- 틱 간격은 정수 마이크로초(50,000)로 다룬다. 실수 delta 를 정수로 바꾸는 일은 표현 레이어의 몫
- `_process`가 아니라 누적 틱 루프에서 시뮬레이션 갱신
- 프레임률이 달라져도 시뮬레이션 결과가 동일해야 함

**3. 모든 상태 변경은 명령 객체 경유**

- 플레이어 입력이 월드 상태를 직접 수정하지 않는다
- 입력 → 명령 객체 생성 → 명령 큐 → 시뮬레이션이 틱 단위로 소비
- 명령은 직렬화 가능해야 함

> 이 세 가지는 나중에 멀티플레이(lockstep)를 얹기 위한 것이면서, 동시에 자동 테스트를 가능하게 한다. 싱글 단계에서도 반드시 지킨다.

**저장은 이 세 규칙의 결과다.**

- 저장 파일에는 **시드와 명령 기록과 틱 수만** 적는다. 상태를 통째로 뜨지 않는다
- 불러올 때는 같은 시드로 섬을 세우고 같은 명령을 같은 차례로 넣은 뒤 그만큼 다시 돌린다
- 스냅숏은 필드 하나만 빠뜨려도 조용히 어긋난다. 이쪽은 규칙이 깨지면 결정론 회귀 테스트가 먼저 운다
- 대가는 불러오는 데 걸리는 시간이다. 재어 보면 **30분 분량이 281ms** 다. 판이 아주 길어져 이것이 거슬리면 그때 스냅숏을 얹는다
- **명령을 거치지 않은 상태 변경은 되살아나지 않는다.** 이것은 한계가 아니라 규칙 3 을 드러내는 자리다

**4. 로직과 표현 분리**

- 시뮬레이션 레이어는 노드 트리·렌더링에 의존하지 않는다. 헤드리스로 단독 실행 가능해야 함
- 표현 레이어는 시뮬레이션 상태를 읽어 그리기만 한다. 역방향 의존 금지
- 폴더로 가른다. 시뮬레이션은 `sim/`, 표현과 입력은 `view/`
- 입력은 예외가 아니다. 상태를 읽어 명령을 만들 뿐 직접 고치지 않는다

## 3. 월드

### 3.1 지형

- 고정 크기 섬 1개. 프로토타입 기준 **64 x 64 x 16** 복셀
- 무한 지형·청크 스트리밍 **없음**
- 지형은 고정 시드로 생성하거나 수작업 배치. 프로토타입에서는 수작업 권장
- 격자 좌표는 **z 가 높이**다. Godot 은 y 가 위이므로 축 바꿈은 표현 레이어에서만 한다
- 지형 블록 4종: `빈칸` / `지면` / `광석` / `나무`
- 그 밖의 블록: `문`(닫힘/열림), `밭`, `감지기`, `작동기`, `되풀이`, `상자`, `갈림길`. 부품도 격자 한 칸을 차지한다
- 열린 문은 지나갈 수 있지만 자리에 남아 있다. 빈 칸과 다르다
- 맨 아래 층(z=0)은 섬의 지반이다. **부술 수 없다.** 뚫리면 딛을 곳 없는 칸이 생겨 캐릭터가 갇힌다
- 블록은 이미 단단한 칸에 붙여서만 놓을 수 있다. 한 칸씩 이어 다리를 놓는 것은 되지만 허공에 홀로 뜬 블록은 만들 수 없다
- 부수면 그 재료가 손에 들어오고, 놓으면 재료를 쓴다. 재료가 없으면 놓지 못한다
- **빈손으로 시작한다.** 첫 블록은 손으로 부숴 얻는다. 제작법이 생겨 `IslandBuilder.GIVE_STARTING_KIT` 는 꺼져 있다. 손으로 살펴볼 일이 있으면 잠깐 켜도 되지만, 켠 채로 두면 광석 자원지가 뜻을 잃는다

### 3.2 낮과 밤

- 1주기 = 실시간 약 10분 (낮 7분 / 밤 3분)
- 밤에는 위협이 출현하고 시야가 좁아짐
- 낮인지 밤인지는 **틱만으로** 정해진다. 따로 들고 있는 상태가 없어 저장·복원에서 어긋나지 않는다
- 해가 지고 뜨는 데 15초가 걸린다. 갑자기 캄캄해지지 않는다
- **밤이 게임의 리듬이자 테스트 사이클이다.** 낮에 만든 장치가 밤에 시험받는다

### 3.3 캐릭터 이동

- 판정은 칸 단위다. 걸을 수 있는지 없는지는 칸으로만 따진다
- 위치는 칸을 1000으로 나눈 정수(서브유닛)로 잡는다. 실수는 쓰지 않는다
- 한 걸음은 여러 틱에 걸친다. 걷는 중에 들어온 걸음 명령은 무시한다. 칸 경계에 정확히 서야 다음 판정이 맞는다
- 방향 전환은 걷는 중에도 받는다
- **여덟 방향.** 동서남북과 그 사이 네 대각선
- 대각선은 **양옆이 모두 열려 있어야** 지나간다. 한쪽이라도 막히면 벽 모서리를 뚫고 가는 꼴이 된다. 이것은 화면에 어떻게 보이는지와 무관한 격자의 문제다
- 대각선도 곧은 걸음처럼 한 칸 턱은 오른다. 오를 때도 양옆이 열려 있어야 한다
- **옆이 막혀 못 가는 것을 턱 오르기로 우회할 수 없다.** 그러면 모서리 규칙이 새어 나간다
- 대각선과 곧은 걸음은 **같은 시간이 걸린다**. 월드에서는 대각선이 sqrt(2) 배 먼 거리지만, 아이소메트릭이 화면 세로를 1/sqrt(3) 만큼 눌러 주어 화면에서 잰 길이가 정확히 같아지기 때문이다
- 몸은 두 칸 높이를 차지한다. 머리 칸이 막히면 지나갈 수 없다
- 한 칸 턱은 오른다. 두 칸은 오르지 못한다
- 낮은 곳으로는 떨어진다. 발밑이 사라지면 다음 틱에 내려앉는다
- **딛을 곳이 없는 칸으로는 나가지 않는다.** 섬 밖 바다로 걸어 나갈 수 없다
- 갈 수 없는 방향이라도 방향 전환은 이뤄진다. 제자리에서 돌아설 수 있어야 놓을 목표를 정한다

칸 사이를 메우는 부드러운 움직임은 표현 레이어의 보간이다. 시뮬레이션 결과에 영향을 주지 않는다.

### 3.4 겨냥

- 마우스가 가리키는 블록을 강조해 보여준다. **어느 칸에 손이 닿는지만 알려준다. 왜 안 되는지는 말하지 않는다**
- 손에 든 것이 무엇을 하는 물건인지 화면 아래에 한 줄로 적는다. 이것은 **조작 안내**지 회로를 고쳐 주는 화면이 아니다
- 조작 안내판은 기본으로 숨긴다. 늘 떠 있으면 화면을 가린다
- 새 블록은 겨냥한 블록의 맞은 면 바깥에 놓인다
- 캐릭터에서 5칸까지만 손이 닿는다
- 겨냥한 곳이 없으면 바라보는 앞 칸을 쓴다. 마우스 없이 키만으로도 놀 수 있어야 한다

### 3.5 시점

아이소메트릭 시점. 직교 투영. 기울기는 고정이고 캐릭터를 따라간다.

- 좌우 회전(45도씩)과 확대는 사람이 정한다. 부품을 놓을 때 가까이 봐야 한다
- **이동 키는 화면 기준이다.** W 는 화면 위쪽이고, 화면과 격자 사이의 회전은 표현 레이어가 카메라에서 뽑는다. 시점을 돌리면 조작도 따라 돈다
- 키 하나로 화면의 위아래좌우, **두 키를 겹쳐 눌러 화면의 네 대각선**. 여덟 쪽 모두 갈 수 있다
- 요 45도에서 화면 위아래좌우는 격자 대각선이고 화면 대각선은 격자 축이다. 요 0도면 그 둘이 뒤바뀐다. 어느 쪽이든 키와 화면은 어긋나지 않는다
- 화면 좌우로 가는 두 방향만 세로 눌림을 받지 않아 빨라 보인다. 블록 자체가 세로보다 가로로 넓은 것과 같은 이치다

> **왜 여덟 방향인가.** 아이소메트릭에서는 격자 축 네 방향이 모두 비스듬히 놓인다.
> 재어 보면 축 방향 한 칸이 화면에서 가로 30.5 · 세로 17.6 이다.
> 그래서 네 방향만으로는 어떤 키도 화면의 위아래와 맞지 않는다.
> 대각선을 더하면 요가 45도일 때 그 네 대각선이 화면의 위아래좌우와 정확히
> 맞아떨어지고, 축 네 방향은 두 키를 겹쳐 누르면 닿는다. 실제로 재면 W 가
> 가로 성분 0.0 으로 곧장 위로 간다.

### 3.6 자원 3종

| 자원 | 획득처 | 용도 |
|---|---|---|
| 목재 | 섬 곳곳의 나무 | 기본 건축, 문 |
| 광석 | 특정 자원지 (거리 있음) | 부품 제작 |
| 작물 | 섬에 난 것을 손으로, 밭에 심은 것은 작동기로 | 식량 |

**자원지는 기지에서 떨어져 있다.** 왕복이 자동 운반 장치의 동기가 된다.

### 제작법

프로토타입 범위는 열 개 이내다(§6). 지금은 일곱이다.

| 만드는 것 | 드는 것 |
|---|---|
| 문 | 나무 4 |
| 밭 | 흙 3 + 나무 1 |
| 감지기 | 광석 2 + 나무 1 |
| 작동기 | 광석 1 + 나무 2 |
| 되풀이 | 광석 3 + 나무 1 |
| 상자 | 나무 3 + 광석 1 |
| 갈림길 | 광석 2 + 나무 2 |

- **부품에는 반드시 광석이 든다.** 그래야 떨어진 자원지를 오가는 일에 뜻이 생긴다
- 흙·돌·나무·작물은 만들지 못한다. 손으로 얻는 것이다
- **묶음은 제작법이 없다.** 재료가 아니라 이미 지어 놓은 회로를 압축해 얻는다 (§4.3)
- 만드는 데 걸리는 시간도, 제작대도 없다. 재료가 있으면 그 틱에 만들어진다. 회로가 코어이고 나머지는 최소한만 둔다
- 재료가 하나라도 모자라면 **아무것도 쓰지 않고** 실패한다. 반쯤 쓰고 실패하면 재료만 사라진다
- 드는 재료는 화면 아래 한 줄에 적는다. 모자란지는 말하지 않는다. 손에 든 것은 핫바에 다 적혀 있다

- **섬에 저절로 난 작물이 흩어져 있다.** 손으로 부숴 얻는다. 다시 나지 않는다
  - 이것이 없으면 첫날 밤에 닿을 수가 없다. 배는 4분에 비고 5분 40초에 쓰러지는데 첫 밤은 7분에 온다
  - 첫날은 이것으로 넘기고, 둘째 날부터는 밭과 작동기가 필요해진다. §6 의 완료 판정 기준이 겨누는 자리가 거기다
- 밭 블록을 놓으면 심긴다. 90초면 다 자란다. 다 자란 뒤에는 더 자라지 않는다
- 거두는 것은 작동기뿐이다. 손으로는 거두지 못한다. 한 번에 작물 2개
- 거두고 나면 다시 처음부터 자란다
- 작물 하나를 먹으면 포만도가 4 찬다
- **심고 → 자라고 → 거두고 → 먹는다.** 이 고리가 닫혀야 생존이 성립한다

### 3.7 생존 지표

- **체력**: 위협에게 피해를 입으면 감소. 0이면 사망 → 리스폰. 최대 20
- **포만도**: 시간에 따라 감소. 0이면 체력이 서서히 감소. 최대 20
- 포만도는 12초에 1씩 준다. 가득 찬 배가 다 비는 데 4분
- 배가 빈 뒤에는 5초마다 체력이 1씩 준다. 굶주림은 갑작스럽지 않다
- 리스폰 시 **인벤토리의 절반을 떨어뜨린다**. 건축물과 회로는 그대로 유지
- 되살아나면 포만도는 절반만 찬다

### 3.8 위협 1종

밤에만 출현하는 단순 적대 개체 1종. 플레이어와 건축물에 접근해 피해를 준다.

- AI는 최소한으로: 가장 가까운 목표로 직선 이동 → 접촉 시 피해
- **AI도 결정론적이어야 한다.** 시드 고정 RNG 사용
- 밤이 시작될 때 4마리가 나온다. 날이 밝으면 사라진다
- 사람에게서 12칸 넘게 떨어진 곳에 나온다. 자리는 시드 고정 난수로 고른다
- 사람보다 느리다. 0.6초에 한 칸
- 길이 막히면 3초 뒤 앞을 부순다. 섬의 바닥층은 부수지 못한다
- 움직임 자체에는 난수를 쓰지 않는다. 자리 고르기에만 쓴다

## 4. 회로 시스템 — 코어

### 4.1 신호 모델

- 신호는 **값을 가진다**. 단순 on/off가 아님
- 값 타입 3종: `정수` / `실수` / `불리언`
- **실수는 1000배 한 정수로 담는다.** 3.7 은 3700 이다. 시뮬레이션에 부동소수점을 들이지 않으면서 실수의 뜻을 지키기 위한 것이다. 눈금(1/1000)보다 잘게는 나타내지 못하며 그것이 이 게임에서 실수의 정밀도다
- 신호는 부품 간 배선을 따라 흐르며, 1틱에 1부품씩 전파
- 배선은 방향이 있다. 출발에서 도착으로만 흐른다
- 부품을 걷어내면 거기 이어진 배선도 함께 사라진다
- 신호가 없는 상태(`없음`)와 거짓인 불리언은 다르다
- **회로에서 "실행된다"는 곧 "신호가 있다"이다.** 값은 그 위에 실린다. 그래서
  - 감지기는 조건을 만족할 때만 신호를 낸다. 만족하지 않으면 거짓이 아니라 아무것도 내지 않는다
  - 작동기와 되풀이는 신호가 닿았는지로 움직인다. 값이 참인지 거짓인지로 움직이지 않는다
  - 갈림길은 택한 쪽으로만 신호를 내보내고 반대쪽은 비운다
- 이 규약의 대가: **없음을 조건으로 삼을 수 없다.** "사람이 없을 때"를 감지하려면 그런 대상을 가진 감지기가 따로 있어야 한다
- 배선에는 출구 번호가 있다. 갈림길만 출구가 둘이고 나머지는 하나다

### 4.2 부품 5종

#### (1) 감지기 — 입력

무엇을 볼지 **설치 시 지정**한다. 지정 대상이 조건을 만족하면 신호를 출력.

| 대상 | 출력 |
|---|---|
| 플레이어 | 근접 시 불리언 참 |
| 위협 | 근접 시 불리언 참, 거리를 정수로 |
| 시간 | 밤이면 불리언 참 |
| 작물 | 성숙했으면 불리언 참 |
| 아이템 | 개수를 정수로 |

> **개념: 매개변수.** 같은 부품인데 지정한 대상에 따라 다르게 동작한다.

근접은 3칸이다. 다섯 대상 모두 실제로 동작한다.
위협 감지기는 근접한 위협까지의 거리를 정수로 내보낸다.

#### (2) 상자 — 처리

값 하나를 담는다. 신호로 넣고, 신호로 꺼낸다.

- **모양이 있다**: 네모(정수) / 둥근(실수) / 작은(불리언)
- 맞는 모양의 값은 그대로 저장
- **안 맞는 값은 들어가되 깎인다**: 3.7 → 네모 상자 → 3. 되돌려도 3.7은 복구되지 않음
- 새 값을 넣으면 이전 값은 사라진다

> **개념: 변수, 자료형, 형변환 손실, 대입.**
> 깎임은 게임적으로 실제 손해여야 한다. 수확량 3.7이 3이 되면 실제로 1을 잃는다.

- 담긴 값은 늘 밖으로 나가고 있다. 배선을 이으면 언제든 읽을 수 있다
- 신호가 오지 않는 동안에는 담긴 값이 그대로 남는다
- **거짓은 신호가 없는 것과 다르다.** 거짓도 상자에 들어간다
- 배선이 여럿이면 먼저 이어진 쪽 값이 들어간다

#### (3) 갈림길 — 처리

조건을 판정해 신호를 한쪽으로만 보낸다.

- 참 → A 출구, 거짓 → B 출구
- **거짓일 때 A 쪽은 실행되지 않는 것이 시각적으로 보여야 한다**
- 조건에 상자를 물리면 비교 가능 (`상자값 >= 10`)
- 갈림길을 연결하면 else-if 사슬
- 입력 두 개를 물리면 AND / OR 선택 가능

> **개념: 조건문, 비교연산, 논리연산, 분기.**
> AND/OR는 별도 부품으로 만들지 않는다. 배선으로 발명하게 한다.

- 값은 바꾸지 않는다. 어느 쪽으로 보낼지만 정한다. 그래야 갈림길을 이어 사슬을 만들 수 있다
- 판정 방식: 참/거짓 그대로 · `>=` · `<` · `==` · AND · OR
- 실수와 견줄 때 깎이지 않는다. 2.9 는 `>= 3` 을 만족하지 않는다
- 신호가 오지 않으면 어느 쪽으로도 나가지 않는다
- **흐르지 않는 배선은 흐린 색으로 보인다.** 왜 흐르지 않는지는 말하지 않는다
- 참 쪽 배선과 거짓 쪽 배선은 색이 다르다. 어느 쪽에 이었는지 눈으로 구별된다
- 배선을 이을 때 갈림길을 출발점으로 잡으면 어느 출구에서 나갈지 고를 수 있다. 지금 고른 출구는 화면에 보인다

#### (4) 되풀이 — 처리

받은 신호를 정한 간격으로 반복 출력한다.

- **횟수 지정**: N번 반복 후 정지 (for)
- **조건 지정**: 조건이 참인 동안 반복 (while)
- **미지정**: 무한 반복

무한 반복은 정상 동작이지만 대가가 있다. **장치가 과열되어 정지하고, 소모된 자원은 돌아오지 않는다.** 파괴적이지 않되 명백한 손해.

- 되풀이는 신호가 끊겼다 들어올 때 새로 시작한다. 참인 채로 머물러 있다고 다시 시작하지 않는다
- 쉬는 동안 식는다. 그래서 정해진 만큼만 도는 되풀이는 아무리 여러 번 써도 타지 않는다
- 40번 내보내면 과열된다. 타 버린 부품은 **부숴도 재료가 돌아오지 않는다**
- 되풀이하는 것은 값이다. 켜짐/꺼짐이 아니라 받은 신호를 그대로 되풀이한다

> **개념: 반복문, 종료조건, 무한루프.**

#### (5) 작동기 — 출력

**붙어 있는 블록을 작동시킨다.** 무엇을 하는지는 붙인 블록이 정하고, 언제 하는지만 회로가 정한다.

| 붙인 블록 | 동작 |
|---|---|
| 문 | 열기/닫기 |
| 밭 | 수확 |
| 발사대 | 발사 |
| 등 | 점등/소등 |

> **개념: 부수효과.** 회로가 세계를 바꾸는 유일한 지점.
> 이 설계 덕분에 나중에 블록을 추가해도 회로 부품은 늘지 않는다.

붙어 있는 블록이란 맞닿은 여섯 칸 전부를 말한다. 들어온 신호 중 하나라도 참이면 작동한다.

**문은 사람이 서 있는 칸에서는 닫히지 않는다.** 몸이 블록에 갇히면 안 된다.

### 4.3 묶음 — 핵심 기능

완성한 회로를 선택해 **하나의 부품으로 압축**한다.

- **입력 단자 지정** → 배치할 때마다 다른 값을 넣을 수 있음 (매개변수)
- **출력 단자 지정** → 결과를 밖으로 내보냄 (반환값)
- **내부는 감춰진다** → 밖에서 안 보임 (캡슐화)
- **묶음 안의 상자는 밖에서 접근 불가.** 같은 묶음을 10개 배치하면 각각 자기 상자를 가짐 (스코프)
- **묶음 안에 묶음을 넣을 수 있다** (추상화 계층)
- 압축된 묶음은 인벤토리에 들어가 몇 개든 재배치 가능

> **개념: 함수, 매개변수, 반환값, 지역 스코프, 추상화.**
> **이 기능이 이 게임의 정체성이다.** 없으면 그냥 레드스톤이고, 있으면 이 게임이다. 프로토타입에 반드시 포함.

**재귀는 구현하지 않는다.** 묶음이 자기 자신을 참조하는 것은 금지. 묶음 번호는 만든 차례대로 붙고 설계도는 자기보다 작은 번호만 품을 수 있다. 그래서 서로 물고 도는 일 자체가 생기지 않는다.

- 묶으려면 칸을 고르고 그중에서 값이 드나들 자리를 정한다. **고른 차례가 곧 드나드는 차례다.** 첫째 배선이 첫째 들어오는 자리에 닿고, 첫째 나가는 자리가 첫째 출구다
- 신호가 없는 배선도 자리를 차지한다. 어느 배선이 어느 자리로 가는지가 신호의 있고 없음에 따라 흔들리면 안 된다
- **나가는 자리는 그 부품의 첫 출구다.** 갈림길의 거짓 쪽을 밖으로 내보내려면 안에서 다른 부품으로 받아 그것을 또 하나의 나가는 자리로 삼는다
- **안에 든 감지기와 작동기는 묶음이 놓인 칸에서 세상을 만난다.** 묶음은 한 칸짜리 부품이므로 그 안이 어디에 그려져 있었는지는 세상과 상관이 없다
- 안쪽 회로도 한 틱에 한 부품씩 나아간다. 묶음이 틱을 더 먹지는 않는다
- 고른 칸 밖으로 나가거나 밖에서 들어오던 배선은 함께 가지 않는다. 부품이 사라지면 그 배선도 사라진다
- **타 버린 부품은 묶지 못한다.** 묶어서 되살릴 수 있으면 과열의 대가가 대가가 아니게 된다. 안에서 탄 묶음은 부숴도 돌아오지 않는다
- 묶는 것은 부수는 것이 아니다. **삼킨 부품은 재료로 돌아오지 않는다**
- 묶음은 종류 번호만으로 가려지지 않으므로 인벤토리에서 묶음 번호마다 따로 센다

- 표지판 (포인터/참조)

후반 콘텐츠. 프로토타입 검증 후 추가.

## 6. 프로토타입 범위

- 섬 1개 (64x64x16), 수작업 배치
- 낮밤 주기
- 자원 3종, 제작법 10개 이내 (§3.6 에 일곱 개)
- 위협 1종
- 부품 5종 + 묶음 기능
- 캐릭터 이동, 채집, 블록 배치/파괴
- 저장/불러오기 (단일 슬롯). `user://save.json`, F5 로 적고 F9 로 되살린다. 형식은 §2 참조

### 제외

전투 시스템, 몹 다양화, 무한 지형, 던전, 인챈트, 차원, 멀티플레이, NPC, 의뢰 시스템, 튜토리얼 이상의 서사

### 완료 판정 기준

> **"첫날 밤을 손으로 버티고, 둘째 날 회로를 만들고 싶어지는가."**

이 감정이 나오면 성공. 안 나오면 부품이 아니라 **난이도 수위 조절 문제**다. 부품을 늘리기 전에 수위를 먼저 조정한다.

### 단계별 검증 순서

1. 감지기 + 작동기로 자동문 → **조작감이 재밌는가**
2. 되풀이 추가 → 자동 농장
3. 상자 + 갈림길 → 야간 통합 시스템
4. 묶음 → 만든 걸 압축해 재배치

**1번이 재미없으면 부품을 늘려도 소용없다.** 여기서 멈추고 조작을 다시 설계한다.

## 7. 테스트 전략

결정론적 시뮬레이션이므로 **"이 배치 + 이 명령 시퀀스 → 이 상태"** 를 그대로 못박을 수 있다.

### 유닛 테스트 (GdUnit4)

- 각 부품의 단독 동작
- 신호 전파 타이밍 (1틱 1부품)
- 상자 형변환 손실 정확성 (3.7 → 정수 상자 → 3)
- 되풀이 종료조건 / 무한 시 과열 처리
- 묶음 스코프 격리 (묶음 A의 상자를 묶음 B에서 읽을 수 없음)

### 결정론 회귀 테스트 — 가장 중요

```
초기 월드 시드 + 명령 시퀀스 → N틱 실행 → 월드 상태 해시
```

같은 입력에 대해 해시가 항상 같아야 한다. **이 테스트가 깨지면 결정론이 깨진 것이고, 멀티플레이 가능성이 사라진다.** CI에서 매 커밋 실행.

### E2E (PlayGodot)

- 자동문 조립 → 플레이어 접근 → 문 열림
- 밤 진입 → 야간 시스템 작동
- 스크린샷 캡처 후 시각 검증

### 실행 명령

```bash
# 헤드리스 실행
godot --headless --path . --quit

# GdUnit4 전체 테스트
godot --headless --path . -s res://addons/gdUnit4/bin/GdUnitCmdTool.gd -a test -c --ignoreHeadlessMode

# E2E
pytest tests/ -v
```

1. **검증 인프라 구축** — Godot 프로젝트 뼈대, GdUnit4 설치, 통과/실패 테스트 각 1개, CI 설정
2. **시뮬레이션 코어** — 틱 루프, 명령 큐, 결정론 회귀 테스트
3. **월드** — 복셀 격자, 렌더링, 캐릭터 이동, 블록 배치/파괴
4. **회로 최소** — 감지기 + 작동기 → 자동문. **여기서 조작감 판정**
5. **회로 확장** — 되풀이 → 상자 → 갈림길
6. **생존** — 낮밤, 자원, 포만도, 위협
7. **묶음** — 압축, 단자 지정, 스코프 격리
8. **판정** — 첫날 밤 → 둘째 날 회로 욕구가 생기는가

**1번은 사람이 직접 한다.** 에이전트에게 맡기면 자기가 통과하기 쉬운 테스트를 만든다.

## 9. 개념 대응표 (내부 참조용 — 게임 내 노출 금지)

| 게임 요소 | 개념 |
|---|---|
| 상자 | 변수, 대입 |
| 상자 모양 | 자료형 |
| 모양 안 맞을 때 깎임 | 형변환 손실 |
| 갈림길 | 조건문, 분기 |
| 갈림길 + 상자 비교 | 비교연산 |
| 갈림길 입력 2개 | 논리연산 (AND/OR) |
| 되풀이 (횟수) | for |
| 되풀이 (조건) | while |
| 되풀이 (무한) | 무한루프 |
| 감지기 대상 지정 | 매개변수 |
| 작동기 | 부수효과 |
| 묶음 | 함수 |
| 묶음 입력 단자 | 매개변수 |
| 묶음 출력 단자 | 반환값 |
| 묶음 내부 은닉 | 캡슐화, 지역 스코프 |
| 묶음 중첩 | 추상화 계층 |
| *(후반)* 연결대 | 배열, 인덱스 |
| *(후반)* 연결대 경계 초과 | 버퍼 오버런 |
| *(후반)* 표지판 | 포인터, 참조 |
| *(후반)* 사라진 대상의 표지판 | 댕글링 포인터 |

**게임 화면에 프로그래밍 용어를 노출하지 않는다.** 이 표는 설계 검수용이다.

### 검수 원칙

부품 동작이 실제 의미론과 **어긋나서는 안 된다.** 단순화는 허용하되 반대로 가르치면 안 됨.

- 갈림길이 랜덤 분기여서는 안 된다
- 묶음 안의 상자가 밖에서 보여서는 안 된다
- 형변환 손실이 되돌려져서는 안 된다

이 검수는 사람이 한다.
