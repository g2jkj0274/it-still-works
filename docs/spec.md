# 회로 생존 샌드박스 — 프로토타입 스펙 v0.1

> 상시 적용 규칙은 루트의 `CLAUDE.md`에 있다. 이 문서는 부품 명세와 범위를 정의한다.

> 이 문서는 프로토타입 범위만 정의한다. 여기 없는 것은 만들지 않는다.

---

## 1. 개요

아이소메트릭 복셀 섬에서 살아남는 생존 샌드박스. 낮에는 자원을 모으고 회로 장치를 만들고, 밤에는 그 장치가 시험받는다.

**생존이 목적이고 회로는 수단이다.** 회로 없이도 손으로 살아남을 수 있지만, 반복 노동이 쌓여 점점 힘들어진다. 회로는 강제가 아니라 유혹이다.

### 설계 원칙

| 원칙 | 내용 |
|---|---|
| 회로가 코어 | 개발 시간의 대부분을 회로 시스템에 쓴다. 나머지는 최소한만 |
| 원인을 알려주지 않음 | 에러 메시지 없음. 장치의 동작만 보이고 원인은 플레이어가 추론 |
| 실패는 가벼움 | 죽으면 리스폰. 만든 것은 남음 |
| 목표를 강제하지 않음 | 게이팅 없음. 부품은 처음부터 다 열려 있음 |
| 손으로도 되지만 힘듦 | 불가능이 아니라 반복. 첫 번째는 재밌고 열 번째는 지겹게 |

### 소리

- **소리는 표현 레이어가 낸다.** 시뮬레이션은 소리를 모른다. 재생 함수를 시뮬레이션에서 부르면 헤드리스 단독 실행이 깨진다(§2-4)
- 명령을 넣었을 때가 아니라 **세상이 실제로 바뀌었을 때** 운다. 재료가 없어 못 놓았으면 소리도 나지 않는다. 화면과 소리가 같은 것을 말한다
- 프로토타입에서 필요한 것은 열몇 개다. 부수기 · 놓기 · 걸음 · 만들기 · 잇기 · 신호가 지남 · 문 여닫힘 · 과열 · 얻어맞음 · 먹기 · 해가 지고 뜸
- **신호가 부품을 지날 때 나는 짧은 소리**가 이 장르의 정체성이다. 회로가 돌고 있다는 것이 그때 처음 감각이 된다
- 발소리는 **가로로 한 칸 옮겼을 때** 난다. 떨어지는 칸마다 울리면 벼랑을 내려오는 것이 뛰어가는 소리로 들린다. 닿는 순간에 한 번이면 족하다

### 막힌 것을 알리는 것

- **아무 일도 안 일어나는 것이 가장 나쁜 답이다.** 손이 차면 부수기가 통째로 막히는데, 화면에서는 키가 안 먹는 것과 구별되지 않았다. 누르고 또 눌러도 세상이 그대로면 게임이 고장 난 것으로 읽힌다
- 무엇이 막았는지는 말하지 않는다. "원인을 알려주지 않음"은 그대로다. **눌린 것이 닿았고 세상은 그대로다**만 알린다 — 둔한 소리 하나와 손에 잡히는 줄의 짧은 흔들림
- 규칙을 표현 레이어에 옮겨 적지 않는다. 손이 찼는지 궤짝이 비었는지를 화면이 다시 판단하면 언젠가 시뮬레이션과 어긋나고, 어긋난 신호는 없느니만 못하다. **명령을 낸 다음 세상이 그대로인지만 본다**

### 아트 방향

메이플스토리2 톤. 아이소메트릭 고정 시점, 파스텔, 복셀. 밝고 경쾌함. 무겁거나 무서운 연출 없음. 프로토타입 단계에서는 CC0 에셋 또는 단색 프리미티브로 대체.

- 색은 `view/palette.gd` 한 곳에 모은다. 새 블록을 넣을 때도 여기만 고친다
- **명도 0.60 이상, 채도 0.45 이하.** 파스텔의 경계이며 테스트가 지킨다
- 파스텔은 쓸 수 있는 폭이 좁다. 색상환에 고르게 펴야 종류가 구별된다
- 같은 종류라도 칸마다 명도를 아주 조금 달리해 넓은 면이 한 덩어리로 보이지 않게 한다. 자리에서 값을 뽑으므로 무늬는 실행마다 같다
- 캐릭터는 치비 비율. 머리가 크고 몸이 작다
- 그림자는 부드럽게. 또렷한 그림자는 톤을 무겁게 만든다

## 2. 기술 스택

- **엔진**: Godot 4.x
- **언어**: GDScript (성능 병목 발생 시 해당 부분만 C#)
- **테스트**: GdUnit4 (유닛), PlayGodot (E2E)
- **버전관리**: Git, 기능당 브랜치

### 아키텍처 규칙 — 필수

**1. 결정론적 시뮬레이션**

같은 초기 상태 + 같은 명령 시퀀스 → 항상 같은 결과.

- 위치·수량은 정수 격자만 사용. 시뮬레이션 로직에 부동소수점 금지
- 난수는 시드 고정된 단일 RNG 인스턴스 경유. `randi()` 전역 호출 금지
- 딕셔너리 순회 등 순서 비보장 자료구조를 시뮬레이션 판단에 사용 금지
- `StringName` 끼리의 비교는 사전순이 아니라 내부 포인터 순이다. `Array[StringName].sort()` 는 실행마다 순서가 달라진다. 정렬이 필요하면 `String` 으로 바꾼 뒤 정렬

**2. 틱 기반 고정 시간**

- 시뮬레이션은 고정 20 tick/s 로 진행. 렌더 프레임과 분리
- 틱 간격은 정수 마이크로초(50,000)로 다룬다. 실수 delta 를 정수로 바꾸는 일은 표현 레이어의 몫
- `_process`가 아니라 누적 틱 루프에서 시뮬레이션 갱신
- 프레임률이 달라져도 시뮬레이션 결과가 동일해야 함

**3. 모든 상태 변경은 명령 객체 경유**

- 플레이어 입력이 월드 상태를 직접 수정하지 않는다
- 입력 → 명령 객체 생성 → 명령 큐 → 시뮬레이션이 틱 단위로 소비
- 명령은 직렬화 가능해야 함

> 이 세 가지는 나중에 멀티플레이(lockstep)를 얹기 위한 것이면서, 동시에 자동 테스트를 가능하게 한다. 싱글 단계에서도 반드시 지킨다.

**저장은 이 세 규칙의 결과다.**

- 저장 파일에는 **시드와 명령 기록과 틱 수만** 적는다. 상태를 통째로 뜨지 않는다
- 불러올 때는 같은 시드로 섬을 세우고 같은 명령을 같은 차례로 넣은 뒤 그만큼 다시 돌린다
- 스냅숏은 필드 하나만 빠뜨려도 조용히 어긋난다. 이쪽은 규칙이 깨지면 결정론 회귀 테스트가 먼저 운다
- 대가는 불러오는 데 걸리는 시간이다. 재어 보면 **30분 분량이 281ms** 다. 판이 아주 길어져 이것이 거슬리면 그때 스냅숏을 얹는다
- **명령을 거치지 않은 상태 변경은 되살아나지 않는다.** 이것은 한계가 아니라 규칙 3 을 드러내는 자리다

**4. 로직과 표현 분리**

- 시뮬레이션 레이어는 노드 트리·렌더링에 의존하지 않는다. 헤드리스로 단독 실행 가능해야 함
- 표현 레이어는 시뮬레이션 상태를 읽어 그리기만 한다. 역방향 의존 금지
- 폴더로 가른다. 시뮬레이션은 `sim/`, 표현과 입력은 `view/`
- 입력은 예외가 아니다. 상태를 읽어 명령을 만들 뿐 직접 고치지 않는다

## 3. 월드

### 3.1 지형

- 고정 크기 섬 1개. **64 x 64 x 24** 복셀
  - 세로는 위아래가 다 필요하다. 지표 아래로 파고 내려갈 만큼, 그 위로 쌓아 올릴 만큼
  - 한동안 지면이 두 층뿐이었고 그중 아래는 부술 수 없었다. **팔 수 있는 땅이 한 층이라 캐는 일이 성립하지 않았다**
- 무한 지형·청크 스트리밍 **없음**
- 지형은 고정 시드로 생성하거나 수작업 배치. 프로토타입에서는 수작업 권장
- 격자 좌표는 **z 가 높이**다. Godot 은 y 가 위이므로 축 바꿈은 표현 레이어에서만 한다
- 지형 블록 5종: `빈칸` / `흙` / `돌` / `광석` / `나무`
  - **흙**은 지표에서 두 칸까지다. 윗면은 풀, 옆면은 흙으로 보인다
  - **돌**은 그 아래를 이루는 흔한 암반이다. 쌓는 데도 쓴다
  - **광물**은 돌 사이에 광맥으로 든다. 깊을수록 **귀하다** *미구현*
  - 광물이 하나뿐일 때는 "깊을수록 흔하다"가 맞았다. 다섯으로 갈린 지금은 그것이
    뒤집힌다 — 재어 보면 지금 광맥은 z1 에 446칸, z6 에 123칸이라 **가장 깊은
    띠에 가장 많이 들어 있다.** 그대로 두면 제일 귀해야 할 빛돌이 제일 흔해진다
  - 마인크래프트의 다이아가 값진 것은 깊어서가 아니라 **깊고 적어서**다.
    깊이는 문을 열 뿐이고 희소성은 따로 정해야 한다

| 광물 | 띠 | 섬 전체 목표 | 어떤 것 |
|---|---|---|---|
| 불씨돌 | z3~7 | 약 600 | 가장 흔하다. 굽는 것 전부에 든다 |
| 광석 | z2~6 | 약 600 | 부품의 재료 |
| 깊은광 | z1~3 | 약 120 | 귀하다 |
| 빛돌 | z1~2 | 약 40 | 가장 귀하다 |

  - 한 광물은 **자기 띠 안에서는** 깊을수록 잘 든다. 다만 띠가 깊을수록 그
    광물의 총량이 적다. 그래야 "더 내려간다"가 "더 많이 캔다"가 아니라
    "더 좋은 것을 조금 캔다"가 된다
  - 넷을 합쳐 약 1360칸이다. 지금 광맥 칸이 1693이므로 남는 자리는 돌로 둔다.
    광맥이 나는 빈도 자체는 건드리지 않는다
  - **지금은 둘로만 갈라 두었다**(`IslandBuilder.EMBER_FLOOR_Z`). 깊은광과
    빛돌이 없기 때문이다. 재어 보면 불씨돌 846칸(z3~6) · 광석 847칸(z1~2)
    이고, 그래서 **광석이 목표 띠(z2~6)보다 깊다.** 넷으로 가를 때 올라온다.
    첫 회로는 지상 자원지 69칸으로 닿으므로 막히지 않는다
- 지표는 기복을 탄다. 좌표에서 뽑으므로 실행마다 같은 섬이 나오고 난수를 쓰지 않는다
- **이웃한 기둥끼리 한 칸 넘게 벌어지지 않는다.** 캐릭터는 한 칸 턱만 오르므로(§3.3) 두 칸 절벽이 흔해지면 섬이 걸어 다닐 수 없는 곳이 된다. 여기저기 절벽이 있는 것은 괜찮다
- 땅속에는 빈 곳이 있다. 파고 내려갈 이유이고 광맥이 드러나는 자리다
- **광석은 어둠을 덜 먹는다.** 벽에 박혀 있어도 캄캄해서 검은 벽과 구별되지 않으면, 굴을 파도 어디로 갈지 모른 채 아무 데나 파게 된다. 등불 밖에서도 형체가 남을 만큼만 띄운다 — 대낮처럼 밝히는 것이 아니다
- **광맥은 드러난 벽에 더 잘 든다.** 바위 속에만 들면 굴을 파고 들어가도 회색 벽뿐이라, 어디를 파야 할지 몰라 아무 데나 파게 된다. 벽에 박힌 광석이 눈에 걸려야 그것이 목적지가 된다
- 벽에만 나지는 않는다. 벽의 것을 캐고 나면 더 파고 들어갈 까닭이 남아야 한다
- 물가는 고르게 한 높이로 눕는다. 들쭉날쭉하면 물낯을 어디에 두어도 어떤 곳은 잠기고 어떤 곳은 절벽이 된다
- 바다는 섬 바깥에만 있다. 평평한 판으로 깔면 땅을 파 내려가는 순간 구덩이에 물이 차 보인다 — 시뮬레이션에는 빈 칸인데 화면이 물이라고 말하는 것이다
- 그 밖의 블록: `문`(닫힘/열림), `등`(꺼짐/켜짐), `궤짝`, `밭`, `감지기`, `작동기`, `되풀이`, `상자`, `갈림길`. 부품도 격자 한 칸을 차지한다
- §3.6 이 더하는 블록: `모래`, `불씨돌`, `깊은광`, `빛돌`, `화로`, `작업대`, `벽돌`, `유리`, `튼튼한 문`(닫힘/열림), `밝은 등`(꺼짐/켜짐), `발사대`, `밀개`, `놓개`, `종`, `손잡이`(젖힘/내림), `관솔불`, `다듬은 돌`, `빛벽돌`. **아직 구현되지 않았다**
- 뒤의 셋(`밀개`·`놓개`·`종`)은 작동기가 다루는 블록이다. §4.2 를 함께 볼 것. **부품이 아니라 블록이다** — 부품은 다섯 종 그대로다
- **광물은 깊이로 갈린다.** 광석은 z ≤ 6, 불씨돌은 z ≤ 5, 깊은광은 z ≤ 3, 빛돌은 z ≤ 2. 한 층을 다 캐면 더 내려갈 까닭이 남아 있어야 한다
- **켜진 등은 둘레를 밝힌다.** 땅속은 지표에서 멀어질수록 어둡다. 그래서 파고 내려가려면 등이 필요해진다
- 등의 세기는 그 자리가 얼마나 어두운가를 따른다. 한밤중이거나 깊이 묻혔으면 온 힘을 내고, **한낮 지표에서는 있는 듯 마는 듯하다.** 낮에도 같은 세기로 때리면 바닥이 하얗게 날아가 켜진 등이 아니라 잘못 그려진 흰 상자로 보인다
- 열린 문은 지나갈 수 있지만 자리에 남아 있다. 빈 칸과 다르다
- 맨 아래 층(z=0)은 섬의 지반이다. **부술 수 없다.** 뚫리면 딛을 곳 없는 칸이 생겨 캐릭터가 갇힌다
- **놓아서 짓는 데 쓰는 것은 열 가지다.** *일부 미구현*
  - 흙 · 돌 · 나무 · 모래 — 캔 것을 그대로 놓는다
  - 판자 · 벽돌 · 다듬은 돌 · 유리 · 빛벽돌 — 만든 것을 놓는다
  - 관솔불 — 놓으면 작게 밝힌다. **작동기가 여닫지 못한다.** 늘 켜져 있는 것이
    등과 다른 점이고, 그래서 회로 없이도 굴을 밝힐 수 있다
  - 아이템 수로 보면 마인크래프트의 다양성 대부분이 건축 블록이다.
    우리 쪽에서 그것이 하는 일은 **지은 회로를 감추고 꾸미는 것**이다.
    배선과 부품 표시가 눈에 잘 띄게 그려지므로(§4.1) 가릴 것이 있어야 한다
  - **형태가 다른 블록(계단 · 반블록)은 두지 않는다.** 한 칸이 한 블록이라는
    격자 규칙과 이동 판정(§3.3)을 건드린다. 늘리는 것은 **빛깔과 무늬**까지다
- 블록은 이미 단단한 칸에 붙여서만 놓을 수 있다. 한 칸씩 이어 다리를 놓는 것은 되지만 허공에 홀로 뜬 블록은 만들 수 없다
- 부수면 그 재료가 손에 들어오고, 놓으면 재료를 쓴다. 재료가 없으면 놓지 못한다

### 손에 드는 것

- 인벤토리는 **36칸이고 칸마다 64개까지** 쌓인다. 앞 9칸이 손에 잡히는 줄이다
  - 한계가 없으면 무엇을 가져갈지 고르는 일이 없고, 그러면 자원지를 오가는 일에 값이 붙지 않는다. §3.6 의 "왕복이 자동 운반 장치의 동기"가 성립하려면 **손이 먼저 모자라야 한다**
  - 칸 하나는 [무엇, 몇 개, 어느 것] 이다. **어느 것**은 묶음처럼 종류만으로는 가려지지 않는 물건의 자리다
- **손이 차면 부수지 못한다.** 부수고 나서 버리면 조용히 사라지고, 땅에 떨어뜨리자니 떨어진 것을 주울 길이 없다
- 고르는 것은 종류가 아니라 **칸**이다. 빈 칸을 잡을 수도 있다
- **궤짝**에 넣어 둔다. 27칸이다. 손이 모자란 것이 짜증이 아니라 살림이 되려면 넣어 둘 곳이 있어야 한다
  - 안이 빈 궤짝만 걷어낼 수 있다. 부수면 안의 것이 조용히 사라진다
- 칸에서 칸으로 옮기는 것도 **명령을 거친다**. 화면이 인벤토리를 직접 고치면 저장한 판을 되살렸을 때 물건이 제자리로 돌아간다
- **빈손으로 시작한다.** 첫 블록은 손으로 부숴 얻는다. 제작법이 생겨 `IslandBuilder.GIVE_STARTING_KIT` 는 꺼져 있다. 손으로 살펴볼 일이 있으면 잠깐 켜도 되지만, 켠 채로 두면 광석 자원지가 뜻을 잃는다

### 3.2 낮과 밤

- 1주기 = 실시간 약 10분 (낮 7분 / 밤 3분)
- 밤에는 위협이 출현하고 시야가 좁아짐
- **밤은 어두운 낮이 아니다.** 밝기만 낮추면 초록이 그대로 초록이라 흐린 낮이 된다. 달빛의 **빛깔**을 파랑 쪽으로 돌려 명도를 크게 낮추지 않고도 밤이 되게 한다
- 며칠째인지, 지금이 낮인지 밤인지, 해가 어디쯤 기울었는지는 화면에 상시로 보인다. **리듬은 예고될 때만 리듬이다**
- 낮인지 밤인지는 **틱만으로** 정해진다. 따로 들고 있는 상태가 없어 저장·복원에서 어긋나지 않는다
- 해가 지고 뜨는 데 15초가 걸린다. 갑자기 캄캄해지지 않는다
- **밤이 게임의 리듬이자 테스트 사이클이다.** 낮에 만든 장치가 밤에 시험받는다

### 3.3 캐릭터 이동

- 판정은 칸 단위다. 걸을 수 있는지 없는지는 칸으로만 따진다
- 위치는 칸을 1000으로 나눈 정수(서브유닛)로 잡는다. 실수는 쓰지 않는다
- 한 걸음은 여러 틱에 걸친다. 걷는 중에 들어온 걸음 명령은 무시한다. 칸 경계에 정확히 서야 다음 판정이 맞는다
- 방향 전환은 걷는 중에도 받는다
- **여덟 방향.** 동서남북과 그 사이 네 대각선
- 대각선은 **양옆이 모두 열려 있어야** 지나간다. 한쪽이라도 막히면 벽 모서리를 뚫고 가는 꼴이 된다. 이것은 화면에 어떻게 보이는지와 무관한 격자의 문제다
- 대각선도 곧은 걸음처럼 한 칸 턱은 오른다. 오를 때도 양옆이 열려 있어야 한다
- **옆이 막혀 못 가는 것을 턱 오르기로 우회할 수 없다.** 그러면 모서리 규칙이 새어 나간다
- 대각선과 곧은 걸음은 **같은 시간이 걸린다**. 월드에서는 대각선이 sqrt(2) 배 먼 거리지만, 아이소메트릭이 화면 세로를 1/sqrt(3) 만큼 눌러 주어 화면에서 잰 길이가 정확히 같아지기 때문이다
- 몸은 두 칸 높이를 차지한다. 머리 칸이 막히면 지나갈 수 없다
- 한 칸 턱은 오른다. 두 칸은 오르지 못한다
- **한 칸 턱은 내려선다.** 오르는 것과 같은 시간이 걸린다. 오르내리는 손맛이 다르면 비탈이 계단으로 느껴진다
- 두 칸 이상 아래는 턱이 아니라 벼랑이다. 같은 높이로 걸어 나가고, 떨어지는 것은 그 다음이다
- 낮은 곳으로는 떨어진다. 발밑이 사라지면 다음 틱에 내려앉는다
- **떨어지는 중에는 걸음이 시작되지 않는다.** 그러지 않으면 이동 키를 누르고 있는 동안 낙하가 차례를 얻지 못해 그 높이 그대로 허공을 걸어간다
- 빠른 것은 **곧게 떨어질 때**뿐이다. 가로로 나아가며 함께 내려가는 것은 걸음이고 걸음 속도로 간다
- **딛을 곳이 없는 칸으로는 나가지 않는다.** 섬 밖 바다로 걸어 나갈 수 없다
- 갈 수 없는 방향이라도 방향 전환은 이뤄진다. 제자리에서 돌아설 수 있어야 놓을 목표를 정한다

칸 사이를 메우는 부드러운 움직임은 표현 레이어의 보간이다. 시뮬레이션 결과에 영향을 주지 않는다.

### 3.4 겨냥

- 마우스가 가리키는 블록을 강조해 보여준다. **어느 칸에 손이 닿는지만 알려준다. 왜 안 되는지는 말하지 않는다**
- 손에 든 것이 무엇을 하는 물건인지 화면 아래에 한 줄로 적는다. 이것은 **조작 안내**지 회로를 고쳐 주는 화면이 아니다
- 조작 안내판은 기본으로 숨긴다. 늘 떠 있으면 화면을 가린다
- 새 블록은 겨냥한 블록의 맞은 면 바깥에 놓인다
- 캐릭터에서 5칸까지만 손이 닿는다
- 겨냥한 곳이 없으면 바라보는 앞 칸을 쓴다. 마우스 없이 키만으로도 놀 수 있어야 한다

### 3.5 시점

아이소메트릭 시점. 직교 투영. 기울기는 고정이고 캐릭터를 따라간다.

- 좌우 회전(45도씩)과 확대는 사람이 정한다. 부품을 놓을 때 가까이 봐야 한다
- **이동 키는 화면 기준이다.** W 는 화면 위쪽이고, 화면과 격자 사이의 회전은 표현 레이어가 카메라에서 뽑는다. 시점을 돌리면 조작도 따라 돈다
- 키 하나로 화면의 위아래좌우, **두 키를 겹쳐 눌러 화면의 네 대각선**. 여덟 쪽 모두 갈 수 있다
- 요 45도에서 화면 위아래좌우는 격자 대각선이고 화면 대각선은 격자 축이다. 요 0도면 그 둘이 뒤바뀐다. 어느 쪽이든 키와 화면은 어긋나지 않는다
- 화면 좌우로 가는 두 방향만 세로 눌림을 받지 않아 빨라 보인다. 블록 자체가 세로보다 가로로 넓은 것과 같은 이치다

> **왜 여덟 방향인가.** 아이소메트릭에서는 격자 축 네 방향이 모두 비스듬히 놓인다.
> 재어 보면 축 방향 한 칸이 화면에서 가로 30.5 · 세로 17.6 이다.
> 그래서 네 방향만으로는 어떤 키도 화면의 위아래와 맞지 않는다.
> 대각선을 더하면 요가 45도일 때 그 네 대각선이 화면의 위아래좌우와 정확히
> 맞아떨어지고, 축 네 방향은 두 키를 겹쳐 누르면 닿는다. 실제로 재면 W 가
> 가로 성분 0.0 으로 곧장 위로 간다.

### 3.6 자원과 제작

> **0~2단은 구현되었다. 3단 위는 아직 설계다.** 제작법 서른다섯 가운데
> **열다섯**이 코드에 있다 — 판자 · 도구 넷 · 관솔불 · 문 · 궤짝 · 밭 ·
> 부품 다섯 종 · 등.
>
> 아직 없는 것: **화로와 작업대**, 그리고 그 위의 것 전부(쇳덩이 · 깊은
> 것들 · 밀개 · 놓개 · 종 · 발사대 · 손잡이 · 건축 블록). 만드는 자리가
> 손뿐이므로 **트리가 3단에서 멈춘다.**
>

#### 왜 다시 설계했나

제작법 아홉 개는 **두 단짜리 평면**이었다. 손으로 얻는 것 다섯 가지가 곧바로
물건이 되고 거기서 끝난다. 캐면 나오고 나오면 만들어진다. 고를 것이 없고,
어제 못 하던 것을 오늘 하게 되는 순간이 없다.

- 파낸 돌 12817개가 어느 제작법에도 들지 않았다
- 작물은 먹는 것 말고 쓰임이 없었다
- 광석은 첫날에도 마지막 날에도 같은 광석이었다. **깊이 내려갈 이유가 없었다**
- 도구가 없어 첫 시간과 열 번째 시간의 손이 똑같았다

#### 다시 설계한 원칙

1. **가공은 회로가 돌린다.** 굽는 일은 손으로 못 한다. 화로는 작동기가 때려야
   돈다. 그래서 테크트리가 코어 시스템과 다투지 않고 **그것을 쓸 이유가 된다**.
   되풀이 → 작동기 → 화로가 곧 자동 제련소다
2. **첫 자동문은 여전히 둘째 날에 닿는다.** §6 의 완료 판정 기준이 거기 걸려
   있다. 깊이는 자동문 **위에** 쌓지, 그 앞에 놓지 않는다
3. **부품은 다섯 종 그대로다.** 늘어나는 것은 재료 · 도구 · 작업 블록이다.
   §4.2 는 손대지 않는다
4. **깊이는 세로에서 얻는다.** 세계가 z=24 이고 지하가 비어 있다. 광물 등급을
   깊이로 가른다. 좋은 것은 아래에 있다
5. **이름에 프로그래밍 용어를 쓰지 않는다**(§1). 전부 물건 이름이다

#### 자원 — 깊이가 등급이다

| 자원 | 어디에 | 맨손으로 | 쓰임 |
|---|---|---|---|
| 나무 | 지표의 나무 | 얻는다 | 판자 |
| 흙 | 지표에서 두 층 | 얻는다 | 밭, 메우기 |
| 모래 | 물가 | 얻는다 | 유리 |
| 작물 | 야생 14곳, 밭 | 얻는다 | 식량 |
| 돌 | 흙 아래 전부 | **못 얻는다** | 화로, 벽돌, 도구 |
| 광석 | 지상 자원지 3곳, z ≤ 6 광맥 | **못 얻는다** | 부품, 쇳덩이 |
| 불씨돌 | z ≤ 5 | **못 얻는다** | 굽는 데 드는 것 |
| 깊은광 | z ≤ 3 | **못 얻는다** | 깊은쇳덩이 |
| 빛돌 | z ≤ 2 | **못 얻는다** | 밝은 등 |

- **위에서 아래로 갈수록 좋고, 아래로 갈수록 도구가 있어야 한다.** 이것이 깊이를
  파고 내려갈 이유다. 지금은 광맥 하나뿐이라 한 번 내려가면 더 내려갈 까닭이 없다
- 지상 자원지는 그대로 둔다. 다만 이제 **곡괭이가 있어야 캔다**
- 불씨돌과 빛돌도 벽에 드러나게 둔다(§3.1). 어둠 속 회색 벽에서 무엇을 캘지
  눈이 잡아야 한다

#### 도구 — 무엇을 캘 수 있는지를 가른다

도구는 손에 들면 쓰인다. 고르는 것은 칸이다(§3.1 손에 드는 것).

| 도구 | 만드는 것 | 캘 수 있는 것 |
|---|---|---|
| 맨손 | — | 나무 · 흙 · 모래 · 작물 |
| 나무 곡괭이 | 판자 3 | + 돌 · **불씨돌** |
| 돌 곡괭이 | 판자 2 + 돌 3 | + 광석 |
| 쇠 곡괭이 | 판자 2 + 쇳덩이 3 | + 깊은광 · 빛돌 |
| 깊은쇠 곡괭이 | 판자 2 + 깊은쇳덩이 3 | 전부. 가장 빠르다 |
| 돌 도끼 | 판자 2 + 돌 3 | 나무를 빠르게 |
| 쇠 도끼 | 판자 2 + 쇳덩이 3 | 나무를 더 빠르게 |
| 돌 삽 | 판자 2 + 돌 1 | 흙과 모래를 빠르게 |

- **불씨돌은 나무 곡괭이로 캔다.** 처음에는 돌 곡괭이를 요구했는데, 그러면
  **첫 굴에 빛이 없다.** 등은 광석이 들고 광석은 돌 곡괭이가 있어야 하는데,
  파고 내려가기 시작하는 것은 나무 곡괭이일 때다. 어두운 곳에 위협이 나게 된
  지금(§3.8) 빛 없는 첫 굴은 그냥 죽는 길이다.
  마인크래프트에서 횃불의 재료인 석탄이 나무 곡괭이로 캐지는 자리가 여기다
- **맞는 도구가 없으면 부숴지지도 않는다.** 부숴는 지는데 아무것도 안 나오는
  쪽은 "고장 났나"로 읽힌다. 손이 닿지 않는다는 것이 화면에 보여야 한다(§1 막힘)
- 도구는 닳지 않는다. 내구도는 프로토타입에서 제외한다. **고르는 재미는 등급에서
  나오지 관리에서 나오지 않는다**
- 도구가 캐는 속도를 정한다. 지금은 무엇이든 다섯 틱이다

#### 만드는 자리 셋

**어디서 만들 수 있는가가 곧 테크트리의 마디다.** 재료만으로는 층이 생기지 않는다.

| 자리 | 어떻게 | 무엇을 |
|---|---|---|
| 손 | 언제나 | 판자 · 기본 도구 · 문 · 궤짝 · 밭 · 화로 · 부품 5종 · 등 |
| **화로** | **작동기가 때려야 한 번 돈다** | 굽는 것 전부 |
| 작업대 | 세 칸 안에 서서 | 쇳덩이가 드는 것 |

- **화로는 손으로 못 돌린다.** 이것이 이 설계의 중심이다. 첫 회로가 자동문이
  아니라 화로가 될 수도 있다 — 어느 쪽이든 **둘째 날에 회로를 만들 이유**가 하나
  더 생긴다(§6)
- 화로는 신호 한 번에 한 번 굽는다. 굽는 데 걸리는 시간은 없다. 시간은 신호를
  얼마나 자주 주느냐가 정한다. **되풀이의 간격이 곧 제련 속도다**
- 재료는 인벤토리에서 뺀다. 화로에 넣어 두는 칸은 없다. 넣어 두는 것은 궤짝이다
- 작업대는 사람이 쓴다. 회로가 아니라. 둘을 갈라 두어야 "회로가 없으면 못 하는
  것"이 무엇인지가 분명해진다

#### 제작법

**아래 서른다섯 가운데 열다섯이 구현되어 있다.** 손에서 만드는 것 전부와
부품 다섯 종 · 등이다. 화로와 작업대가 없으므로 그 두 자리의 것은 아직 없다.

프로토타입 범위는 **35개**다. 아홉 개였고, 그 상한이 열 개였다(§6). 두 단짜리
평면을 여섯 단으로 세우는 데 필요한 수를 세어 다시 잡았다.

**손에서 — 첫날**

| 만드는 것 | 드는 것 |
|---|---|
| 판자 (4개) | 나무 1 |
| 나무 곡괭이 | 판자 3 |
| 돌 곡괭이 | 판자 2 + 돌 3 |
| 돌 도끼 | 판자 2 + 돌 3 |
| 돌 삽 | 판자 2 + 돌 1 |
| 문 | 판자 4 |
| 궤짝 | 판자 6 |
| 밭 | 흙 3 + 판자 1 |
| 화로 | 돌 8 |
| **손잡이** | 판자 2 |
| **관솔불** (4개) | 판자 1 + 불씨돌 1 |

**손에서 — 부품 5종과 등**

| 만드는 것 | 드는 것 |
|---|---|
| 감지기 | 광석 2 + 판자 1 |
| 작동기 | 광석 1 + 판자 2 |
| 되풀이 | 광석 3 + 판자 1 |
| 상자 | 판자 3 + 광석 1 |
| 갈림길 | 광석 2 + 판자 2 |
| 등 (2개) | 판자 1 + 광석 1 |

**화로에서 — 작동기가 때려야 돈다**

| 만드는 것 | 드는 것 |
|---|---|
| 쇳덩이 | 광석 1 + 불씨돌 1 |
| 깊은쇳덩이 | 깊은광 1 + 불씨돌 2 |
| 벽돌 | 돌 1 + 불씨돌 1 |
| **다듬은 돌** | 돌 1 + 불씨돌 1 |
| 유리 | 모래 1 + 불씨돌 1 |
| 숯 | 나무 2 + 불씨돌 1 |
| 구운 작물 | 작물 1 + 불씨돌 1 |

- **숯은 불씨돌을 대신한다.** 나무는 다시 나지 않지만 이것이 있으면 땅속에
  들어가지 않고도 조금은 돈다. 손해 보는 환율이다 — 나무 둘에 하나
- 구운 작물은 포만도를 8 채운다. 날것은 4다(§3.7)

**작업대에서 — 쇳덩이**

| 만드는 것 | 드는 것 |
|---|---|
| 작업대 | 판자 4 + 쇳덩이 2 |
| 쇠 곡괭이 | 판자 2 + 쇳덩이 3 |
| 쇠 도끼 | 판자 2 + 쇳덩이 3 |
| 튼튼한 문 | 쇳덩이 4 |
| **밀개** | 판자 3 + 쇳덩이 1 |
| **놓개** | 판자 2 + 쇳덩이 2 |
| **종** | 쇳덩이 3 |

**작업대는 도구와 장치의 자리다.** 손으로는 부품을 만들고, 작업대에서는
그 부품이 다룰 것을 만든다. 이 셋이 §5 의 장치 절반을 연다.

**작업대에서 — 깊은 곳이 열린 뒤**

| 만드는 것 | 드는 것 |
|---|---|
| 깊은쇠 곡괭이 | 판자 2 + 깊은쇳덩이 3 |
| 밝은 등 (2개) | 유리 1 + 빛돌 1 |
| **빛벽돌** (2개) | 벽돌 1 + 빛돌 1 |
| **발사대** | 깊은쇳덩이 3 + 판자 2 · 탄은 돌 (§4.2) |

- **발사대가 이 트리의 끝이다.** §4.2 의 작동기 표와 §5 의 자동 방어에 발사대가
  적혀 있는데 만들 길이 없었다. 이제 트리의 마지막 칸이 그것이다. 다섯 장치
  가운데 유일하게 못 짓던 것이 **가장 깊은 곳까지 내려가야 열리는 것**이 된다
- **튼튼한 문은 위협이 부수지 못한다.** 밤에 회로를 지키는 값이 생긴다(§3.8)

#### 규칙은 그대로다

- **부품에는 반드시 광석이 든다.** 떨어진 자원지를 오가는 일에 뜻이 생긴다
- 흙 · 돌 · 나무 · 모래 · 작물은 만들지 못한다. 손으로 얻는 것이다
- **묶음은 제작법이 없다.** 이미 지어 놓은 회로를 압축해 얻는다(§4.3)
- 재료가 하나라도 모자라면 **아무것도 쓰지 않고** 실패한다
- 드는 재료는 화면 아래 한 줄에 적는다. 모자란지는 말하지 않는다
- 만드는 데 걸리는 시간은 없다. 화로도 신호 한 번에 한 번이다

#### 나무를 심는다

> *미구현.* **판자가 제작법 32개 가운데 21개에 든다.** 그런데 섬에 나무가
> 30칸뿐이고 다시 나지 않는다. 마르면 도구도 부품도 장치도 더 만들 수 없다 —
> 트리 전체가 거기서 선다. 마인크래프트가 묘목을 둔 자리가 여기다.

- **흙 윗면 바로 위에 놓은 나무는 뿌리를 내린다.** 3분이면 위로 두 칸이 더
  자라 세 칸 나무가 된다. 나무 1 이 나무 3 이 된다
- 다른 나무 위나 돌 위에 놓은 것은 그냥 블록이다. 벽으로 쌓는 길이 막히지 않는다
- **위로 세 칸이 비어 있어야 자란다.** 막혀 있으면 뿌리만 내린 채로 머문다
- 밭과 같은 구조다. 놓으면 심기고, 시간이 지나면 자라고, 다 자란 뒤에는
  더 자라지 않는다
- **거두는 것은 손이다.** 밭과 다르다 — 밭은 작동기로만 거두는데 나무는 손으로 벤다.
  나무가 없으면 작동기를 만들 수 없으므로 작동기를 요구하면 고리가 물린다
- 도끼가 있으면 빨리 벤다(§3.6 도구)

#### 작물과 밭

- **섬에 저절로 난 작물이 흩어져 있다.** 손으로 부숴 얻는다. 다시 나지 않는다
  - 이것이 없으면 첫날 밤에 닿을 수가 없다. 배는 4분에 비고 5분 40초에 쓰러지는데 첫 밤은 7분에 온다
  - 첫날은 이것으로 넘기고, 둘째 날부터는 밭과 작동기가 필요해진다. §6 의 완료 판정 기준이 겨누는 자리가 거기다
- 밭 블록을 놓으면 심긴다. 90초면 다 자란다. 다 자란 뒤에는 더 자라지 않는다
- 거두는 것은 작동기뿐이다. 손으로는 거두지 못한다. 한 번에 작물 2개
- 거두고 나면 다시 처음부터 자란다
- 작물 하나를 먹으면 포만도가 4 찬다. 구우면 8이다
- **심고 → 자라고 → 거두고 → 먹는다.** 이 고리가 닫혀야 생존이 성립한다

### 3.7 생존 지표

- **체력**: 위협에게 피해를 입으면 감소. 0이면 사망 → 리스폰. 최대 20
- **포만도**: 시간에 따라 감소. 0이면 체력이 서서히 감소. 최대 20
- 포만도는 12초에 1씩 준다. 가득 찬 배가 다 비는 데 4분
- 배가 빈 뒤에는 5초마다 체력이 1씩 준다. 굶주림은 갑작스럽지 않다
- 리스폰 시 **인벤토리의 절반을 떨어뜨린다**. 건축물과 회로는 그대로 유지
- 되살아나면 포만도는 절반만 찬다

### 3.8 위협 1종

밤에만 출현하는 단순 적대 개체 1종. 플레이어와 건축물에 접근해 피해를 준다.

- AI는 최소한으로: 가장 가까운 목표로 직선 이동 → 접촉 시 피해
- **사람과 한눈에 갈려야 한다.** 파스텔 폭이 좁아 색은 믿을 수 없다. 사람은 서 있는 치비, 이것은 납작하고 넓은 덩어리이며 걸을 때 통통 튄다
- 무섭게 만들지 않는다(§1). 튀는 젤리 덩어리다
- **AI도 결정론적이어야 한다.** 시드 고정 RNG 사용
- **어두운 칸에서 난다. 시각이 아니라 밝기가 기준이다.** *미구현*
  - 여태 규칙은 "밤에 지표에서"였다. 그런데 자리를 고르는 것이 "그 기둥에서 설 수
    있는 가장 낮은 칸"이라 **재어 보면 넷 중 둘쯤(44%)이 지표 아래 5~9칸,
    즉 굴 안에서 난다.** 사람에게 닿지도 못하고 밤이 조용해진다
  - 동시에 **낮에 파고 내려가는 데는 아무 대가가 없다.** 트리 전체가 깊이 축인데
    깊이가 위험하지 않다. 마인크래프트에서 다이아가 값진 것은 거기까지 가는 길이
    위험하기 때문이다
  - 밝기로 바꾸면 셋이 한꺼번에 풀린다. 지표는 밤에 어두우니 **밤은 지금과 같이**
    오고, 땅속은 늘 어두우니 **낮에도 굴에서 난다.** 그리고 **등이 밝힌 자리에서는
    나지 않는다** — 지금 등은 보이게 하는 것뿐인데 여기서 진짜 쓸모가 생긴다
- 한 번에 4마리까지, 섬 전체에 8마리까지. 사람에게서 **8~14칸 떨어진 띠** 안에서
  나온다. 자리는 시드 고정 난수로 고른다
- 날이 밝으면 **밝아진 자리의 것만** 사라진다. 땅속의 것은 남는다
  - 너무 가까우면 나오자마자 붙어 피할 틈이 없고, 너무 멀면 화면 밖이라 다가오는 것을 볼 수 없다
  - 멀리서 다가오는 것을 몇 초 보는 것이 밤의 긴장 전부다. 낮에 만든 장치가 밤에 시험받는다는 것도 그때 전달된다
- 사람보다 느리다. 0.6초에 한 칸
- **사람과 같은 중력을 받는다.** 단에서 내려오면 내려앉고, 밑을 파내면 떨어진다. 허공에 뜬 채 맴돌면 그것만으로 고장으로 읽힌다
- 길이 막히면 3초 뒤 앞을 부순다. 섬의 바닥층은 부수지 못한다
- **튼튼한 문도 부수지 못한다**(§3.6). 밤에 회로를 지키는 값이 거기서 생긴다
- **체력 3.** 발사대의 돌 세 발에 사라진다(§4.2). *미구현* — 지금은 체력이 없다
  - 한 방이면 발사대 하나로 밤이 끝나고 되풀이를 쓸 이유가 없어진다. 세 발이어야
    연사가 필요해지고 자동 방어가 회로다워진다
- 움직임 자체에는 난수를 쓰지 않는다. 자리 고르기에만 쓴다

## 4. 회로 시스템 — 코어

### 4.1 신호 모델

- 신호는 **값을 가진다**. 단순 on/off가 아님
- 값 타입 3종: `정수` / `실수` / `불리언`
- **실수는 1000배 한 정수로 담는다.** 3.7 은 3700 이다. 시뮬레이션에 부동소수점을 들이지 않으면서 실수의 뜻을 지키기 위한 것이다. 눈금(1/1000)보다 잘게는 나타내지 못하며 그것이 이 게임에서 실수의 정밀도다
- 신호는 부품 간 배선을 따라 흐르며, 1틱에 1부품씩 전파
- 배선은 방향이 있다. 출발에서 도착으로만 흐른다
- 부품을 걷어내면 거기 이어진 배선도 함께 사라진다
- 신호가 없는 상태(`없음`)와 거짓인 불리언은 다르다
- **회로에서 "실행된다"는 곧 "신호가 있다"이다.** 값은 그 위에 실린다. 그래서
  - 감지기는 조건을 만족할 때만 신호를 낸다. 만족하지 않으면 거짓이 아니라 아무것도 내지 않는다
  - 작동기와 되풀이는 신호가 닿았는지로 움직인다. 값이 참인지 거짓인지로 움직이지 않는다
  - 갈림길은 택한 쪽으로만 신호를 내보내고 반대쪽은 비운다
- 이 규약의 대가: **없음을 조건으로 삼을 수 없다.** "사람이 없을 때"를 감지하려면 그런 대상을 가진 감지기가 따로 있어야 한다
- 배선에는 출구 번호가 있다. 갈림길만 출구가 둘이고 나머지는 하나다
- **배선은 어느 쪽으로 흐르는지 보인다.** 도착 쪽으로 갈수록 가늘어진다. 굵기가 일정하면 방향이 있다는 규칙이 화면에 없는 것과 같다
- **신호가 지나가는 것이 보인다.** 흐르기 시작한 배선 위로 밝은 점 하나가 출발에서 도착으로 달린다. 1틱에 한 부품씩 나아가는 것이 이 게임의 코어인데, 색만 바뀌면 그 걸음이 화면에 없다
- 신호 점은 배선보다 **밝고 굵다.** 배선과 같은 색으로 칠하면 정지 화면에 아무것도 남지 않는다
- 가늘어지는 것은 배선 **전체를 따라** 이어져야 한다. 꺾이는 마디마다 굵기를 하나씩 정하면, 맞닿은 두 부품 사이에서는 가운데 한 토막뿐이라 굵기가 한결같아진다
- 배선은 사람이 보통 서 있는 배율에서 보여야 한다. 바짝 당겨야 보이는 굵기는 없는 것과 같다
- 이 셋은 표현일 뿐이다. 시뮬레이션은 모르고 결정론에 영향을 주지 않는다

### 4.2 부품 5종

#### (1) 감지기 — 입력

무엇을 볼지 **설치 시 지정**한다. 지정 대상이 조건을 만족하면 신호를 출력.

| 대상 | 출력 | |
|---|---|---|
| 플레이어 | 근접 시 불리언 참 | |
| 위협 | 근접 시 불리언 참, 거리를 정수로 | |
| 시간 | 밤이면 불리언 참 | |
| 작물 | 성숙했으면 불리언 참 | |
| 아이템 | 개수를 정수로 | |
| **밝기** | 그 자리가 어두우면 불리언 참, 밝기를 정수로 | *미구현* |
| **눌림** | 바로 위 칸을 무언가 밟고 있으면 불리언 참 | *미구현* |
| **손잡이** | 맞닿은 손잡이가 젖혀져 있으면 불리언 참 | *미구현* |

> **개념: 매개변수.** 같은 부품인데 지정한 대상에 따라 다르게 동작한다.

위협 감지기는 근접한 위협까지의 거리를 정수로 내보낸다.

**얼마나 멀리 보는지도 설정이다.** 근접이 3칸으로 고정되어 있었다. *미구현*

| 설정 | 거리 | 쓰는 자리 |
|---|---|---|
| 딱 앞 | 1칸 | 덫 — 밟은 칸만 겨눈다 |
| 가까이 | 3칸 | 자동문. 지금까지의 유일한 값 |
| 멀리 | 8칸 | 경보 — 물리기 전에 울려야 한다 |

3칸 하나뿐일 때는 덫이 옆 칸에도 걸리고 경보가 물리기 직전에 울렸다.
**같은 부품인데 거리에 따라 다른 장치가 된다** — 대상과 마찬가지로 매개변수다.

### 사람이 회로를 켜는 길 — 손잡이

**여태 신호를 내는 것은 감지기뿐이었고, 감지기는 세계를 볼 뿐 사람 말을 듣지
않았다.** 그래서 문을 손으로 열 수도, 조명을 손으로 끌 수도, 제련소를 손으로
멈출 수도 없었다. 회로는 전부 저 혼자 도는 것이었다.

**손잡이**는 블록이다. 부품이 아니다. 사람이 젖히면 젖혀진 채로 머물고,
맞닿은 감지기가 그것을 본다.

- 젖힌 채로 **머문다.** 눌림과 다르다 — 눌림은 밟는 동안만이고 손잡이는 놓아 둔 대로 있다
- 손잡이 자체는 신호를 내지 않는다. 보는 것은 여전히 감지기다.
  **신호를 내는 것은 감지기뿐이라는 규칙을 깨지 않는다**
- 이것 하나로 **사람이 만든 회로를 사람이 켜고 끌 수 있게 된다.** 손 스위치 문,
  손으로 시작하는 제련소, 밤에만 켜는 조명이 여기서 나온다

**대상을 늘리는 것은 부품을 늘리는 것이 아니다.** 부품은 다섯 종 그대로다.
장치의 수는 대상 × 작동 블록 × 처리 부품으로 곱해서 늘어난다.

- **밝기**는 시간과 다르다. 시간은 섬 전체가 밤인가를 말하고, 밝기는 **이 자리가
  어두운가**를 말한다. 땅속은 한낮에도 어둡다. 굴을 파고 들어가면 저절로 켜지는
  등은 시간으로는 만들 수 없다
- **눌림**은 사람 감지기와 다르다. 사람 감지기는 세 칸 안을 보고 사람만 본다.
  눌림은 **바로 그 칸**을 보고 사람이든 위협이든 본다. 밟는 자리를 정확히
  겨눌 수 있어야 덫과 다리가 성립한다

#### (2) 상자 — 처리

값 하나를 담는다. 신호로 넣고, 신호로 꺼낸다.

- **모양이 있다**: 네모(정수) / 둥근(실수) / 작은(불리언). 놓인 상자 위에 그 모양이 표시로 얹혀 밖에서 보인다
- 맞는 모양의 값은 그대로 저장
- **안 맞는 값은 들어가되 깎인다**: 3.7 → 네모 상자 → 3. 되돌려도 3.7은 복구되지 않음
- 새 값을 넣으면 이전 값은 사라진다 — **덮어쓰는 상자**일 때다
- **넣는 방식도 설정이다.** 덮어쓰기 / 더하기. *미구현*
  - **더하는 상자**는 들어온 값을 담긴 값에 얹는다. 그래서 **셀 수 있다**
  - 여태 셈이 없었다. 상자는 마지막 값만 들고 있고 갈림길은 견주기만 하고
    되풀이는 도는 횟수만 셌다. 밟고 지나간 수를 세거나, 거둔 것을 쌓아
    보거나, 몇 번째인지를 아는 장치를 만들 길이 없었다
  - 모양과는 따로다. 네모 · 둥근 · 작은 × 덮어쓰기 · 더하기 = **여섯 가지**

> **개념: 변수, 자료형, 형변환 손실, 대입.**
> 깎임은 게임적으로 실제 손해여야 한다. 수확량 3.7이 3이 되면 실제로 1을 잃는다.

- 담긴 값은 늘 밖으로 나가고 있다. 배선을 이으면 언제든 읽을 수 있다
- 신호가 오지 않는 동안에는 담긴 값이 그대로 남는다
- **거짓은 신호가 없는 것과 다르다.** 거짓도 상자에 들어간다
- 배선이 여럿이면 먼저 이어진 쪽 값이 들어간다

#### (3) 갈림길 — 처리

조건을 판정해 신호를 한쪽으로만 보낸다.

- 참 → A 출구, 거짓 → B 출구
- **거짓일 때 A 쪽은 실행되지 않는 것이 시각적으로 보여야 한다**
- 조건에 상자를 물리면 비교 가능 (`상자값 >= 10`)
- 갈림길을 연결하면 else-if 사슬
- 입력 두 개를 물리면 AND / OR 선택 가능

> **개념: 조건문, 비교연산, 논리연산, 분기.**
> AND/OR는 별도 부품으로 만들지 않는다. 배선으로 발명하게 한다.

- 값은 바꾸지 않는다. 어느 쪽으로 보낼지만 정한다. 그래야 갈림길을 이어 사슬을 만들 수 있다
- 판정 방식: 참/거짓 그대로 · `>=` · `<` · `==` · AND · OR
- 실수와 견줄 때 깎이지 않는다. 2.9 는 `>= 3` 을 만족하지 않는다
- 신호가 오지 않으면 어느 쪽으로도 나가지 않는다
- **흐르지 않는 배선은 흐린 색으로 보인다.** 왜 흐르지 않는지는 말하지 않는다
- 참 쪽 배선과 거짓 쪽 배선은 색이 다르다. 어느 쪽에 이었는지 눈으로 구별된다
- 배선을 이을 때 갈림길을 출발점으로 잡으면 어느 출구에서 나갈지 고를 수 있다. 지금 고른 출구는 화면에 보인다

### 놓인 부품을 읽는 것

- **놓고 나서도 그 부품이 무엇으로 맞춰져 있는지 알 수 있어야 한다.** 겨냥하면 화면 아래 한 줄에 뜬다
- 이것은 "원인을 알려주지 않음"(§1)에 어긋나지 않는다. **왜 안 도는지가 아니라 무엇으로 놓여 있는지**를 읽어 주는 것이다. 오류 메시지가 아니라 라벨이다
- 추론에는 관찰할 사실이 있어야 한다. 사실 자체가 감춰져 있으면 추론이 아니라 전부 부수고 다시 놓기가 된다
- **겨냥하지 않고도 판 전체가 읽혀야 한다.** 설정으로 갈리는 부품은 그 설정이 지붕 위 표시로 얹힌다. 감지기가 무엇을 보는지, 갈림길이 무엇을 재는지, 되풀이가 어떻게 도는지, 상자가 어떤 모양인지가 밖에서 보인다
- 부품은 다섯 종뿐이고 나머지는 전부 설정으로 갈린다. 설정이 안 보이면 감지기 스무 개가 놓인 판은 하나씩 겨냥해야만 읽을 수 있는 판이 된다
- 표시에 글자와 기호는 쓰지 않는다. 서 있는 것 · 하늘을 보는 접시 · 싹처럼 **뜻이 형태에 담긴 것**만 쓴다(§1 프로그래밍 용어 노출 금지)
- **갈래마다 색을 달리한다.** 형태로 갈래 안을 가르고, 색으로 갈래끼리 가른다. 한 색으로 통일하면 열두 픽셀짜리 같은 색 알갱이 열여덟 종이 되어, 판에 스무 개 놓이면 그냥 알갱이 스무 개다. 금지된 것은 글자와 기호이지 색이 아니다
- 파스텔 규칙(명도 0.60 이상)은 블록 몸통 색의 것이다. 표시는 몸통 **위에** 얹히므로 반대로 톤이 낮아야 읽힌다
- 끝없이 도는 되풀이는 다른 것과 달라 보인다. 그것만 타 버리므로 대가가 예고되어야 한다

#### (4) 되풀이 — 처리

받은 신호를 정한 간격으로 반복 출력한다.

- **횟수 지정**: N번 반복 후 정지 (for)
- **조건 지정**: 조건이 참인 동안 반복 (while)
- **미지정**: 무한 반복

무한 반복은 정상 동작이지만 대가가 있다. **장치가 과열되어 정지하고, 소모된 자원은 돌아오지 않는다.** 파괴적이지 않되 명백한 손해.

- 되풀이는 신호가 끊겼다 들어올 때 새로 시작한다. 참인 채로 머물러 있다고 다시 시작하지 않는다
- 쉬는 동안 식는다. 그래서 정해진 만큼만 도는 되풀이는 아무리 여러 번 써도 타지 않는다
- 40번 내보내면 과열된다. 타 버린 부품은 **부숴도 재료가 돌아오지 않는다**
- 되풀이하는 것은 값이다. 켜짐/꺼짐이 아니라 받은 신호를 그대로 되풀이한다

> **개념: 반복문, 종료조건, 무한루프.**

#### (5) 작동기 — 출력

**붙어 있는 블록을 작동시킨다.** 무엇을 하는지는 붙인 블록이 정하고, 언제 하는지만 회로가 정한다.

| 붙인 블록 | 동작 | |
|---|---|---|
| 문 · 튼튼한 문 | 열기/닫기 | |
| 밭 | 수확 | |
| 등 · 밝은 등 | 점등/소등 | |
| **화로** | 한 번 굽는다 | *미구현* (§3.6) |
| **발사대** | 마주 본 쪽 8칸 안의 첫 몸에게 돌을 쏜다 | *미구현* |
| **밀개** | 마주 본 쪽으로 블록을 한 칸 민다 | *미구현* |
| **놓개** | 맞닿은 궤짝에서 하나를 꺼내 마주 본 빈 칸에 놓는다 | *미구현* |
| **종** | 소리를 낸다 | *미구현* |

> **개념: 부수효과.** 회로가 세계를 바꾸는 유일한 지점.
> 이 설계 덕분에 나중에 블록을 추가해도 회로 부품은 늘지 않는다.

**이 표를 늘리는 것이 장치를 늘리는 길이다.** 위 주석이 처음부터 그렇게 적혀
있었다. 여섯 번째 부품을 만드는 것이 아니라 작동기가 다룰 것을 더 놓는다.

**어느 쪽을 작동시킬지가 설정이다.** *미구현*

| 설정 | 무엇을 |
|---|---|
| 전부 | 맞닿은 여섯 칸. 지금까지의 유일한 동작이고 기본값이다 |
| 한 쪽 | 정한 한 칸만. 여섯 쪽 가운데 하나 |

들어온 신호 중 하나라도 참이면 작동한다.

**작동기만 설정이 없었다.** 감지기는 대상이, 갈림길은 판정이, 되풀이는 갈래가,
상자는 모양이 갈리는데 작동기는 언제나 여섯 칸을 다 쳤다. 그래서 문 둘을
나란히 달면 늘 함께 열리고, 밀개 셋을 붙이면 늘 함께 밀었다.
**정밀한 장치를 만들 길이 없었다.**

밀개 · 놓개 · 발사대가 마주 본 쪽을 갖는 물건이라 더 그렇다. 무엇을 언제
움직일지는 회로가 정하는데 어느 것을 움직일지는 정할 수 없었다.

**문은 사람이 서 있는 칸에서는 닫히지 않는다.** 몸이 블록에 갇히면 안 된다.

세 가지 새 블록의 규칙:

- **밀개**는 지형 블록만 민다. **회로 부품과 궤짝은 밀지 못한다** — 부품이
  옮겨 다니면 배선이 어디에 붙어 있는지가 흔들린다. 사람이나 위협이 밀릴
  자리에 있으면 밀지 않는다. 밀 곳이 막혀 있어도 밀지 않는다. 한 번에 한 칸,
  한 블록이다. 줄줄이 미는 것은 프로토타입에서 제외한다
- **놓개**는 맞닿은 궤짝에서 첫 칸의 것을 하나 꺼내 마주 본 빈 칸에 놓는다.
  궤짝이 없거나 비었거나 놓을 자리가 막혔으면 아무 일도 하지 않는다.
  놓는 규칙은 사람이 놓을 때와 같다(§3.1 — 붙여서만 놓는다)
- **종**은 세계를 바꾸지 않는다. 종이 울렸다는 사실만 남기고 소리를 내는 것은
  화면 쪽이다(§1 — 소리는 표현 레이어가 낸다). **멀리서도 들린다.**
  자리를 가진 다른 소리와 달리 거리에 따라 작아지지 않는 유일한 것이다 —
  섬 반대편에서 울려야 알림이 된다

#### 발사대 — 무엇을 쏘는가

> 오랫동안 이 표에 `발사대 | 발사` 한 줄로만 있었다. 무엇을 쏘는지, 맞으면
> 어떻게 되는지, 사거리도 탄도 적혀 있지 않았다. §3.6 의 테크트리가 이것을
> 마지막 칸으로 삼으면서 빈 칸인 것이 드러났다. 여기서 채운다. **미구현.**

**돌을 쏜다.** 새 탄을 만들지 않는다. 돌은 지하에 12817칸이 있고 트리에서
쓰이는 곳이 화로 · 벽돌 · 도구뿐이라 늘 남는다. 남는 자원에 소비처를 주는 것이
새 자원을 하나 더 만드는 것보다 낫다.

| | |
|---|---|
| 탄 | 돌 1개 |
| 쟁이는 한도 | 16발 |
| 사거리 | 마주 본 쪽으로 **8칸** |
| 위협에게 | 1. **세 번 맞으면 사라진다** |
| 사람에게 | 피해 2 — 위협에게 닿았을 때와 같다 |

- **날아가는 개체를 만들지 않는다.** 마주 본 직선 위에서 사거리 안의 **첫 몸**에
  즉시 맞는다. 막힌 칸이 있으면 거기서 멈추고 아무도 맞지 않는다
  - 개체를 하나 더 두면 그것이 상태 해시 · 저장 · 재생에 전부 얽힌다. §6 은
    **전투 시스템을 프로토타입에서 제외**한다. 발사대는 전투가 아니라 회로의
    출력이다. 사람은 손으로 싸우지 않는다
  - 화면은 짧은 줄 하나를 긋는다. 그것은 표현이고 시뮬레이션은 모른다(§1)
- **앞에 누가 있는지 묻지 않는다.** 사람도 맞는다. 그래야 어디에 놓을지 생각하게
  된다. 왜 맞았는지는 말하지 않는다 — 동작만 보인다(§1)
- **탄은 놓개가 채운다.** 발사대는 스스로 궤짝을 뒤지지 않는다. 궤짝 → 놓개 →
  발사대가 재장전 회로다. **그래서 자동 방어가 쏘는 회로와 채우는 회로 두 겹이
  된다.** §5 가 말하는 "부품이 서로 필요해지는 구조"가 여기서 한 번 더 걸린다
- **탄이 없으면 아무 일도 하지 않는다.** 막힌 것을 알리는 규칙을 따른다(§1) —
  둔한 소리 하나. 왜 안 나가는지는 말하지 않는다
- **위협에게 체력을 준다.** 지금 위협은 체력이 없어 맞으면 곧바로 사라지는 수밖에
  없다. 한 방이면 발사대 하나로 밤이 끝나고 되풀이를 쓸 이유가 없어진다.
  세 발이어야 연사가 필요해지고 자동 방어가 회로다워진다
  - 밤 하나가 위협 넷이므로 돌 12개다. 남아도는 자원이라 아깝지 않되 공짜도 아니다
- 맞은 위협은 밀려나지 않는다. AI 는 최소한으로 둔다(§3.8)

### 4.3 묶음 — 핵심 기능

완성한 회로를 선택해 **하나의 부품으로 압축**한다.

- **입력 단자 지정** → 배치할 때마다 다른 값을 넣을 수 있음 (매개변수)
- **출력 단자 지정** → 결과를 밖으로 내보냄 (반환값)
- **내부는 감춰진다** → 밖에서 안 보임 (캡슐화)
- **묶음 안의 상자는 밖에서 접근 불가.** 같은 묶음을 10개 배치하면 각각 자기 상자를 가짐 (스코프)
- **묶음 안에 묶음을 넣을 수 있다** (추상화 계층)
- 압축된 묶음은 인벤토리에 들어가 몇 개든 재배치 가능

> **개념: 함수, 매개변수, 반환값, 지역 스코프, 추상화.**
> **이 기능이 이 게임의 정체성이다.** 없으면 그냥 레드스톤이고, 있으면 이 게임이다. 프로토타입에 반드시 포함.

**재귀는 구현하지 않는다.** 묶음이 자기 자신을 참조하는 것은 금지. 묶음 번호는 만든 차례대로 붙고 설계도는 자기보다 작은 번호만 품을 수 있다. 그래서 서로 물고 도는 일 자체가 생기지 않는다.

- 묶으려면 칸을 고르고 그중에서 값이 드나들 자리를 정한다. **고른 차례가 곧 드나드는 차례다.** 첫째 배선이 첫째 들어오는 자리에 닿고, 첫째 나가는 자리가 첫째 출구다
- 신호가 없는 배선도 자리를 차지한다. 어느 배선이 어느 자리로 가는지가 신호의 있고 없음에 따라 흔들리면 안 된다
- **나가는 자리는 그 부품의 첫 출구다.** 갈림길의 거짓 쪽을 밖으로 내보내려면 안에서 다른 부품으로 받아 그것을 또 하나의 나가는 자리로 삼는다
- **안에 든 감지기와 작동기는 묶음이 놓인 칸에서 세상을 만난다.** 묶음은 한 칸짜리 부품이므로 그 안이 어디에 그려져 있었는지는 세상과 상관이 없다
- 안쪽 회로도 한 틱에 한 부품씩 나아간다. 묶음이 틱을 더 먹지는 않는다
- 고른 칸 밖으로 나가거나 밖에서 들어오던 배선은 함께 가지 않는다. 부품이 사라지면 그 배선도 사라진다
- **타 버린 부품은 묶지 못한다.** 묶어서 되살릴 수 있으면 과열의 대가가 대가가 아니게 된다. 안에서 탄 묶음은 부숴도 돌아오지 않는다
- 묶는 것은 부수는 것이 아니다. **삼킨 부품은 재료로 돌아오지 않는다**
- 묶음은 종류 번호만으로 가려지지 않으므로 인벤토리에서 묶음 번호마다 따로 센다

### 4.4 프로토타입에서 제외

- 연결대 (배열/인덱스)
- 표지판 (포인터/참조)

후반 콘텐츠. 프로토타입 검증 후 추가.

## 5. 조합 예시 — 이것들이 만들어져야 한다

부품은 다섯 종뿐이지만 **설정**으로 갈린다(§4.2). 그 가짓수가 곧 지을 수 있는
것의 넓이다.

| 부품 | 설정 | 가짓수 |
|---|---|---|
| 감지기 | 대상 8 × 거리 3 | **24** |
| 작동기 | 방향 7 (여섯 쪽 + 전부) | **7** |
| 상자 | 모양 3 × 넣는 방식 2 | **6** |
| 갈림길 | 판정 6 | 6 |
| 되풀이 | 갈래 3 | 3 |
|  | **합** | **46** |

전에는 20이었다 — 감지기 5 · 작동기 1 · 상자 3 · 갈림길 6 · 되풀이 3 · 그리고
작동 블록 4. 늘어난 것은 부품이 아니라 **그 부품으로 말할 수 있는 문장**이다.

아래는 그중 반드시 성립해야 하는 것들이다.

| 장치 | 구성 | |
|---|---|---|
| 자동문 | 감지기(사람) → 작동기(문) | |
| 자동 조명 | 감지기(시간=밤) → 작동기(등) | |
| 자동 농장 | 감지기(작물 성숙) → 되풀이 → 작동기(밭) | |
| **자동 제련소** | 되풀이 → 작동기(화로) | *미구현* |
| **지하 등** | 감지기(밝기) → 작동기(등) | *미구현* |
| **경보** | 감지기(위협) → 작동기(종) | *미구현* |
| **덫문** | 감지기(눌림) → 갈림길(위협인가) → 작동기(밀개) | *미구현* |
| **자동 다리** | 감지기(눌림) → 작동기(놓개) | *미구현* |
| **곳간 지기** | 감지기(물건) → 갈림길(≥ 32) → 작동기(종) | *미구현* |
| **자동 벽** | 되풀이 → 놓개 → 벽이 한 칸씩 선다 | *미구현* |
| 자동 방어 | 감지기(위협) → 갈림길(거리) → 되풀이 → 작동기(발사대) | *미구현* |
| **재장전** | 감지기(물건) → 작동기(놓개) → 궤짝의 돌이 발사대로 | *미구현* |
| 야간 통합 시스템 | 감지기(밤) → 상자 저장 → 갈림길 → 문·등·발사대 동시 제어 | *미구현* |
| **손 스위치 문** | 감지기(손잡이) → 작동기(문) | *미구현* |
| **손으로 켜는 제련소** | 감지기(손잡이) → 되풀이 → 작동기(화로) | *미구현* |
| **손님 세기** | 감지기(눌림·딱 앞) → 상자(더하기) → 갈림길(≥ 3) → 작동기(종) | *미구현* |
| **한 짝만 여는 문** | 감지기(사람) → 작동기(한 쪽) → 나란한 문 중 하나 | *미구현* |

마지막 장치는 **5개 부품을 모두 써야 완성된다.** 부품이 서로 필요해지는 구조를 보장하는 기준점.

**늘어난 것은 장치이지 부품이 아니다.** §4.2 의 감지기 대상 표와 작동기 블록
표를 늘렸을 뿐이고, 부품은 다섯 종 그대로다. 그 표를 늘리는 것이 장치를 늘리는
길이라고 §4.2 의 주석이 처음부터 적어 두고 있었다.

몇 가지는 앞의 것 없이는 성립하지 않는다.

- **지하 등**은 시간으로 못 만든다. 땅속은 한낮에도 어둡다. 밝기 감지기가 있어야 한다
- **덫문**은 눌림 감지기가 있어야 한다. 사람 감지기는 세 칸을 보므로 밟는 자리를 겨눌 수 없다
- **자동 제련소**가 없으면 트리가 §3.6 의 4단에서 멈춘다. 이것은 선택이 아니다
- **손잡이가 없으면 사람은 회로를 켤 수 없다.** 여태 회로는 전부 저 혼자 돌았다.
  손 스위치 문과 손으로 켜는 제련소가 그것을 뒤집는다
- **손님 세기는 더하는 상자 없이는 못 만든다.** 여태 셈이 없었다 — 상자는 마지막
  값만 들고 있고 갈림길은 견주기만 했다
- **한 짝만 여는 문은 작동기 방향 없이는 못 만든다.** 여섯 칸을 다 치면 나란한
  문이 늘 함께 열린다
- **자동 방어는 두 겹이다.** 쏘는 회로와 채우는 회로. 발사대가 스스로 궤짝을
  뒤지지 않기 때문이다(§4.2). 열두 장치 가운데 부품이 서로를 가장 많이
  필요로 하는 자리다

**발사대는 §3.6 테크트리의 마지막 칸이다.** 오랫동안 여기와 §4.2 에만 적혀
있고 만들 길이 없어 자동 방어는 지을 수 없는 장치였다. 이제 깊은쇳덩이로
만든다 — 가장 깊은 곳까지 내려가야 열리는 것이 되었다.

## 6. 프로토타입 범위

### 포함

- 섬 1개 (64x64x16), 수작업 배치
- 낮밤 주기
- **자원 9종, 도구 8종, 제작법 35개, 만드는 자리 3곳** (§3.6)
  - 상한이 열 개였고 아홉을 쓰고 있었다. 그 아홉이 **두 단짜리 평면**이어서
    파낸 돌에 쓸 곳이 없고 깊이 내려갈 이유가 없었다. 여섯 단으로 세우는 데
    필요한 수를 세어 다시 잡았다
  - **부품은 다섯 종 그대로다.** 아래 "부품을 늘리기 전에 수위를 먼저 조정한다"는
    그대로 지킨다. 늘어난 것은 재료 · 도구 · 작업 블록이지 부품이 아니다
- 위협 1종
- 부품 5종 + 묶음 기능
- 캐릭터 이동, 채집, 블록 배치/파괴
- 저장/불러오기 (단일 슬롯). `user://save.json`, F5 로 적고 F9 로 되살린다. 형식은 §2 참조

### 제외

전투 시스템, 몹 다양화, 무한 지형, 던전, 인챈트, 차원, 멀티플레이, NPC, 의뢰 시스템, 튜토리얼 이상의 서사

### 완료 판정 기준

> **"첫날 밤을 손으로 버티고, 둘째 날 회로를 만들고 싶어지는가."**

이 감정이 나오면 성공. 안 나오면 부품이 아니라 **난이도 수위 조절 문제**다. 부품을 늘리기 전에 수위를 먼저 조정한다.

### 단계별 검증 순서

1. 감지기 + 작동기로 자동문 → **조작감이 재밌는가**
2. 되풀이 추가 → 자동 농장 · **자동 제련소**
3. 상자 + 갈림길 → 야간 통합 시스템
4. 묶음 → 만든 걸 압축해 재배치

2번에 제련소가 붙은 것은 §3.6 의 화로 때문이다. **굽는 일을 손으로 못 하게
두면 되풀이를 만들 이유가 자동 농장 하나에서 둘이 된다.** 농장은 안 지어도
살 수 있지만 쇳덩이 없이는 트리가 더 올라가지 않는다.

**1번이 재미없으면 부품을 늘려도 소용없다.** 여기서 멈추고 조작을 다시 설계한다.

## 7. 테스트 전략

결정론적 시뮬레이션이므로 **"이 배치 + 이 명령 시퀀스 → 이 상태"** 를 그대로 못박을 수 있다.

### 유닛 테스트 (GdUnit4)

- 각 부품의 단독 동작
- 신호 전파 타이밍 (1틱 1부품)
- 상자 형변환 손실 정확성 (3.7 → 정수 상자 → 3)
- 되풀이 종료조건 / 무한 시 과열 처리
- 묶음 스코프 격리 (묶음 A의 상자를 묶음 B에서 읽을 수 없음)

### 결정론 회귀 테스트 — 가장 중요

```
초기 월드 시드 + 명령 시퀀스 → N틱 실행 → 월드 상태 해시
```

같은 입력에 대해 해시가 항상 같아야 한다. **이 테스트가 깨지면 결정론이 깨진 것이고, 멀티플레이 가능성이 사라진다.** CI에서 매 커밋 실행.

### E2E (PlayGodot)

- 자동문 조립 → 플레이어 접근 → 문 열림
- 밤 진입 → 야간 시스템 작동
- 스크린샷 캡처 후 시각 검증

### 실행 명령

```bash
# 헤드리스 실행
godot --headless --path . --quit

# GdUnit4 전체 테스트
godot --headless --path . -s res://addons/gdUnit4/bin/GdUnitCmdTool.gd -a test -c --ignoreHeadlessMode

# E2E
pytest tests/ -v
```

## 8. 개발 순서

1. **검증 인프라 구축** — Godot 프로젝트 뼈대, GdUnit4 설치, 통과/실패 테스트 각 1개, CI 설정
2. **시뮬레이션 코어** — 틱 루프, 명령 큐, 결정론 회귀 테스트
3. **월드** — 복셀 격자, 렌더링, 캐릭터 이동, 블록 배치/파괴
4. **회로 최소** — 감지기 + 작동기 → 자동문. **여기서 조작감 판정**
5. **회로 확장** — 되풀이 → 상자 → 갈림길
6. **생존** — 낮밤, 자원, 포만도, 위협
7. **묶음** — 압축, 단자 지정, 스코프 격리
8. **판정** — 첫날 밤 → 둘째 날 회로 욕구가 생기는가

**1번은 사람이 직접 한다.** 에이전트에게 맡기면 자기가 통과하기 쉬운 테스트를 만든다.

**게임 화면에 프로그래밍 용어를 노출하지 않는다.** 이 표는 설계 검수용이다.

### 검수 원칙

부품 동작이 실제 의미론과 **어긋나서는 안 된다.** 단순화는 허용하되 반대로 가르치면 안 됨.

- 갈림길이 랜덤 분기여서는 안 된다
- 묶음 안의 상자가 밖에서 보여서는 안 된다
- 형변환 손실이 되돌려져서는 안 된다

이 검수는 사람이 한다.
